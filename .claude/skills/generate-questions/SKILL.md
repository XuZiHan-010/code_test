# 把知识点转成三种题型

输入是一个章节编号（如 `B1`）或一个专题的文件名（如 `rag`，表示该专题的全部章节）。输出写入 `content/typed/<专题文件名>.json`。

专题文件名、题号前缀的对应关系在 `content/topics.json`。文件格式和校验规则的完整定义在 `specs/001-interview-quiz-system/contracts/content-format.md`，动手前先读它。

## 步骤

1. 读该章的题干（`interview-practice/<专题>.md`）和参考答案（`interview-practice/answers-xiaolin/<专题>.md`）。答案文件可能很大，按章节标题定位后分段读，不要整份读入。
2. 逐个知识点判断题型（见下）。
3. 为选择题写题干和选项。简答题只写 `id` 和 `type`，沿用原题干。
4. 写入 `content/typed/<专题>.json`。文件已存在时只替换目标章节，不动其他章节。新生成或重新生成的章节状态一律写 `draft`。
5. 运行 `npm run content:validate`。有错误就修到没有错误；警告逐条处理，确实无法避免的在汇报里说明。
6. 汇报：每种题型各多少道、处理了哪些警告、哪些题拿不准。

## 怎样判断题型

看参考答案的内容，而不是题干的问法。

| 题型 | 判断标准 | 例子 |
| --- | --- | --- |
| 单选 `single` | 答案的核心是一个明确的事实、判断或选择 | “能不能只凭生成时间判断过期”“定位结果是什么形态” |
| 多选 `multiple` | 答案的核心是一组并列的要点，各项之间没有推理关系 | “要记录哪些来源信息”“优先覆盖哪些条件” |
| 简答 `short` | 答案需要成段解释机制、原因、取舍或对比才说得清 | “为什么要先失效再重建”“三种工具各适合什么情况” |

拿不准时的取舍：

- 一个知识点包含两个以上需要分别解释的问题，做简答，不要为了出选择题丢掉半个知识点。
- 并列要点只有两项，或各项之间有先后因果，做简答或单选，不做多选。
- 不要按比例凑题型。一章全是机制解释就全是简答。

## 选择题怎么写

硬性约束（校验器会检查）：

- 单选恰好 4 个选项、1 个正确。
- 多选 4 到 6 个选项，至少 2 个正确，且不能全部正确。
- 选项 `key` 从 `A` 起连续；选项文字非空且互不相同。
- 题干必须写，可以改写原题干使它适合选项形式，但考查的必须还是原来那个知识点。

内容约束（校验器查不出来，靠这里守住）：

- **选项只取材于同一章的参考答案。** 正确选项是对本题参考答案的转述。干扰项用以下两种方式构造，不得引入这一章原文没有讲过的概念或说法：
  - 把本章里的某个说法改反或改偏（原文说“不能断言”，干扰项写“可以断言”）；
  - 用本章里正确、但回答的不是这道题的说法。
- 干扰项必须确定是错的，或确定答非所问。不要写“某种程度上也对”的选项。
- 多选题的每个正确选项都必须能在参考答案里找到对应的要点。
- 不要用“以上都对”“以上都不对”。
- 题干和选项里不要出现题号，不要引用“原文第几节”。

防止答案从形式上泄露（校验器会给出警告 V13、V14）：

- 单选题的正确选项要分散在 A、B、C、D，同一专题里任何一个位置都不要超过四成。
- 正确选项不要明显比干扰项长。宁可把干扰项写具体一点，也不要让最长的那个总是答案。
- 干扰项的句式、详略要和正确选项一致。

## 文件格式

```json
{
  "prefix": "B",
  "chapters": {
    "B1": {
      "status": "draft",
      "questions": [
        {
          "id": "B1-9",
          "type": "single",
          "stem": "……？",
          "options": [
            { "key": "A", "text": "……", "correct": false },
            { "key": "B", "text": "……", "correct": true },
            { "key": "C", "text": "……", "correct": false },
            { "key": "D", "text": "……", "correct": false }
          ]
        },
        { "id": "B1-1", "type": "short" }
      ]
    }
  }
}
```

章节里必须包含该章在 Markdown 中的每一个题号，各出现一次。

## 不要做的事

- **不要把章节状态写成或改成 `approved`。** 只有项目所有者人工抽查通过后才能改，这是项目原则 III 的要求。重新生成一个已经 `approved` 的章节时，状态要改回 `draft`。
- 不要改 `interview-practice/` 里的题干、参考答案和题号。
- 不要改动、删除或复用任何题号。
- 不要用自己的知识补充或纠正参考答案。参考答案是对原文的转述，题目只考原文讲到的内容。
