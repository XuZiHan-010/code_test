# 给知识点选题型

输入是一个章节编号（如 `B1`）或一个专题的文件名（如 `rag`，表示该专题的全部章节）。输出写入 `content/typed/<专题文件名>.json`；出了新的填空题时，还要同步改题卷里那一题的题干（见“填空题怎么写”）。

专题文件名、题号前缀的对应关系在 `content/topics.json`。文件格式和校验规则的完整定义在 `specs/001-interview-quiz-system/contracts/content-format.md`，动手前先读它。

24 个专题都已经有题型数据，每题都已选定题型，所有章节都是 `draft`。现在用这个 skill 主要是给新收录的章节出题，或按抽查意见重新生成某一章、某一题。

## 步骤

1. 读该章的题干（`interview-practice/<专题>.md`）和参考答案（`interview-practice/answers-xiaolin/<专题>.md`）。答案文件可能很大，按章节标题定位后分段读，不要整份读入。
2. 逐个知识点判断题型（见下）。章节里已有的填空题是人工选定的，原样保留，除非用户明确要求重做。
3. 为选择题写题干和选项，为填空题写题干、空数和顺序要求。简答题只写 `id` 和 `type`，沿用原题干。
4. 写入 `content/typed/<专题>.json`，只替换目标章节，不动其他章节。新生成或重新生成的章节状态一律写 `draft`。
5. 新出的填空题，把题卷里对应那一行的题干改成带标记的填空题干。
6. 运行 `npm run content:validate`。有错误就修到没有错误；警告逐条处理，确实无法避免的在汇报里说明。
7. 汇报：每种题型各多少道、新增了哪些填空题（列题号）、处理了哪些警告、哪些题拿不准。

## 怎样判断题型

看参考答案的内容，而不是题干的问法。

| 题型 | 判断标准 | 例子 |
| --- | --- | --- |
| 单选 `single` | 答案的核心是一个明确的事实、判断或选择 | “能不能只凭生成时间判断过期”“定位结果是什么形态” |
| 多选 `multiple` | 答案的核心是一组并列的要点，每项要一句话才说得清，考的是分辨哪些说法成立 | “要记录哪些来源信息”“优先覆盖哪些条件” |
| 填空 `fill` | 答案的核心是数量确定的一组名称：组成、类别、术语或固定步骤，每项用一个词或短语就能说清 | “Harness 的六层组成”“Context Engineering 的三个实践步骤” |
| 简答 `short` | 答案需要成段解释机制、原因、取舍或对比才说得清 | “为什么要先失效再重建”“三种工具各适合什么情况” |
| 代码 `code` | 原文给出完整可运行实现，且手写该算法本身就是常考题；题干不指定语言，答案文件写成“思路 + Python 参考实现 + 要点”的多行格式（见 content-format.md） | “手写快速排序”“实现 LRU 缓存” |

拿不准时的取舍：

- 一个知识点包含两个以上需要分别解释的问题，做简答，不要为了出选择题或填空题丢掉半个知识点。
- 同样是一组并列要点：每项是一个名称，做填空；每项是一句完整的说法，做多选。
- 并列要点只有两项，或各项之间有先后顺序，不做多选。每项是一个名称的做填空，否则做简答或单选。
- 参考答案里的列举不封闭（“例如”“等”“常见的有”），或者项数要靠自己归纳才数得出来，不做填空。
- 参考答案除了列举还有解释，看哪个是核心：核心是那组名称就做填空，解释留在解答里给用户看；核心是解释就做简答。
- 不要按比例凑题型，也不要求每种题型都出现。每题只选最合适的一种；一章只有一两种题型是正常的，一章全是机制解释就全是简答。

## 选择题怎么写

硬性约束（校验器会检查）：

- 单选恰好 4 个选项、1 个正确。
- 多选 4 到 6 个选项，至少 2 个正确，且不能全部正确。
- 选项 `key` 从 `A` 起连续；选项文字非空且互不相同。
- 题干必须写，可以改写原题干使它适合选项形式，但考查的必须还是原来那个知识点。

内容约束（校验器查不出来，靠这里守住）：

- **选项只取材于同一章的参考答案。** 正确选项是对本题参考答案的转述。干扰项用以下两种方式构造，不得引入这一章原文没有讲过的概念或说法：
  - 把本章里的某个说法改反或改偏（原文说“不能断言”，干扰项写“可以断言”）；
  - 用本章里正确、但回答的不是这道题的说法。
- 干扰项必须确定是错的，或确定答非所问。不要写“某种程度上也对”的选项。
- 多选题的每个正确选项都必须能在参考答案里找到对应的要点。
- 不要用“以上都对”“以上都不对”。
- 题干和选项里不要出现题号，不要引用“原文第几节”。

防止答案从形式上泄露（校验器会给出警告 V13、V14）：

- 单选题的正确选项要分散在 A、B、C、D，同一专题里任何一个位置都不要超过四成。
- 正确选项不要明显比干扰项长。宁可把干扰项写具体一点，也不要让最长的那个总是答案。
- 干扰项的句式、详略要和正确选项一致。

## 填空题怎么写

硬性约束（校验器规则 V15 会检查）：

- 题干必须写，每个空用四个下划线 `____` 表示。题干里别的地方不要出现连续的下划线。
- `blankCount` 是 1 到 20 的整数，必须等于题干里 `____` 的个数。
- `blankOrder` 写 `ordered` 或 `unordered`。
- 不能有 `options`。

内容约束（校验器查不出来）：

- **每个空的答案都必须能在本题的参考答案里找到**，空数等于参考答案列出的项数。不要用自己的知识增减项目。
- 一个空对应一个名称或短语。需要一句话才答得出来的内容不要挖空。现有填空题都是 2 到 6 个空；评分要求每个空都答对才算整题正确，空太多的题做简答。
- 题干要把范围说死，让答案只有参考答案里的那一组：写明是谁的、哪一类、共几项，例如“原文所述 Harness 的六层核心组成是：____、____、____、____、____、____。”
- 题干里不要出现任何一个空的答案，也不要出现题号或“原文第几节”。
- 并列的组成、类别用 `unordered`，各空之间用顿号隔开。
- 固定步骤、位置或含义对应用 `ordered`，并且题干要让人看得出每个空该填什么：步骤写“依次是：____ → ____ → ____”，含义对应则把每个空的说明写在它前面（“规定本次允许做什么的是 ____，决定可用操作能力与资源的是 ____”）。
- 评分只看题干问到的那组名称，所以题干只问名称，不要在一个空里同时要名称和解释。

题卷同步：填空题的题干在题卷和题型数据里各有一份，必须一致。把 `interview-practice/<专题>.md` 里那一题改成：

```markdown
- **M1-22** [填空题·无序] 原文所述 Harness 的六层核心组成是：____、____、____、____、____、____。
```

标记是 `[填空题·无序]` 或 `[填空题·有序]`，与 `blankOrder` 对应；标记后面的文字与 `stem` 逐字相同，`stem` 里不带标记。只改这一行的题干，题号、题序和答案文件都不动。两边是否一致没有校验器检查，改完自己核对一遍。

填空题的数量写在 `interview-practice/README.md` 和 `CLAUDE.md` 里（目前 735 道），新增填空题后把这两处的数字改对。`interview-practice/fill-audit-2026-10-13.md` 是那一天的调整记录，不要往里加。

## 文件格式

```json
{
  "prefix": "B",
  "chapters": {
    "B1": {
      "status": "draft",
      "questions": [
        {
          "id": "B1-9",
          "type": "single",
          "stem": "……？",
          "options": [
            { "key": "A", "text": "……", "correct": false },
            { "key": "B", "text": "……", "correct": true },
            { "key": "C", "text": "……", "correct": false },
            { "key": "D", "text": "……", "correct": false }
          ]
        },
        {
          "id": "B1-14",
          "type": "fill",
          "stem": "……的两类……是：____、____。",
          "blankCount": 2,
          "blankOrder": "unordered"
        },
        { "id": "B1-1", "type": "short" }
      ]
    }
  }
}
```

章节里必须包含该章在 Markdown 中的每一个题号，各出现一次。`blankCount` 和 `blankOrder` 只能出现在填空题上。

代码题和选择题、填空题一样必须写 `stem`（题干不指定语言），不能有 `options`，也不能有 `blankCount`、`blankOrder`（校验规则 V16）：

```json
{ "id": "R2-31", "type": "code", "stem": "用任意语言实现快速排序，对整数数组原地升序排序（空数组、单元素数组和含重复元素的数组也要能正确处理）。" }
```

代码题的参考答案在答案文件里写成多行：题号行写思路，缩进 2 空格的围栏代码块放 Python 参考实现，再写“要点”（列出要覆盖的边界情况和复杂度），引用放在最后一行。格式细节见 content-format.md 的“答案文件的多行格式”。代码题答案上限 8000 字。

## 不要做的事

- **不要把章节状态写成或改成 `approved`。** 只有项目所有者人工抽查通过后才能改，这是项目原则 III 的要求。重新生成一个已经 `approved` 的章节时，状态要改回 `draft`。
- 不要改 `interview-practice/` 里的参考答案和题号。题干只在一种情况下可以改：把一道题做成填空题时，按上面的格式改那一行。
- 不要改动、删除或复用任何题号。
- **代码题的 Python 参考实现必须真正运行验证后再写入**：至少用典型输入和边界输入（空输入、单元素、重复元素等）实际执行一遍，结果正确才能写进答案文件；不要凭印象写“应该能跑”的代码。
- 不要用自己的知识补充或纠正参考答案。参考答案是对原文的转述，题目只考原文讲到的内容。
