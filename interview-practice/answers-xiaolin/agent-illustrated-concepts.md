# 图解 Agent：概念与 OpenClaw 原文章节摘编

仅依据各题所列的小林面试笔记原文章节整理；本文件只整理原文口径，不作现行规格认证。原文未覆盖的部分明确标注，不使用其他网站补充。整理日期：2026-10-13。

## 1. Agent 总览：LLM、Agent、工作模式与协议

原文：[AI Agent 是什么？Agent 面试题万字图解](https://xiaolinnote.com/agent/concept/agent.html)。

- **K1-1** LLM 全称 Large Language Model，即大语言模型，通过学习海量文本数据掌握语言的规律和知识，ChatGPT、Claude、DeepSeek、文心一言的底层都是它；工作原理说白了就是预测下一个字，给它一段话，它根据学到的语言规律一个字一个字往后接。[原文§什么是 LLM？](https://xiaolinnote.com/agent/concept/agent.html#%E4%BB%80%E4%B9%88%E6%98%AF-llm)
- **K1-2** 只会说不会做，能力被困在对话框里，没法操作任何系统；没有记忆，记忆只限于当前对话的上下文窗口，对话一结束就归零；不会用工具，不能上网搜索、查数据库、调 API，回答都来自有截止日期且可能出错的已有知识；不会规划，是被动响应型，没法自主拆解任务、制定计划、分步执行。[原文§LLM 有什么弊端？](https://xiaolinnote.com/agent/concept/agent.html#llm-%E6%9C%89%E4%BB%80%E4%B9%88%E5%BC%8A%E7%AB%AF)
- **K1-3** Agent 就是 LLM 在循环中自主使用工具的系统：LLM 说明核心大脑还是大模型，工具说明它能调用外部能力，循环说明它不是一问一答就结束，而是不断思考、行动、观察结果、再思考，直到任务完成。[原文§那 Agent 是什么？](https://xiaolinnote.com/agent/concept/agent.html#%E9%82%A3-agent-%E6%98%AF%E4%BB%80%E4%B9%88)
- **K1-4** 针对只会说不会做，引入工具调用能力，可调用搜索引擎、数据库、API、代码执行器；针对没有记忆，配备短期记忆和存在外部数据库、可跨对话保留的长期记忆；针对不会用工具，业界推出 MCP 等标准化协议统一工具接入；针对不会规划，具备任务拆解和规划能力，把大目标分解成小步骤逐步执行。[原文§Agent 怎么解决 LLM 的弊端？](https://xiaolinnote.com/agent/concept/agent.html#agent-%E6%80%8E%E4%B9%88%E8%A7%A3%E5%86%B3-llm-%E7%9A%84%E5%BC%8A%E7%AB%AF)
- **K1-5** 大脑即 LLM，负责理解意图、推理判断、决定下一步行动；规划模块，把复杂任务拆解成可执行的步骤；记忆模块，存储和检索信息，让 Agent 在长时间任务中保持连贯；工具模块，是 Agent 的手和脚，让它能跟外部世界互动。[原文§Agent 的核心组成](https://xiaolinnote.com/agent/concept/agent.html#agent-%E7%9A%84%E6%A0%B8%E5%BF%83%E7%BB%84%E6%88%90)
- **K1-6** Workflow 是 LLM 和工具通过预定义的代码路径进行编排的系统，Agent 是 LLM 动态主导自身流程与工具调用的系统，由 LLM 自主决定如何完成任务；用大白话说，Workflow 是开发者告诉你每一步该做什么，Agent 是告诉你目标、你自己决定怎么做。[原文§两者的定义](https://xiaolinnote.com/agent/concept/agent.html#%E4%B8%A4%E8%80%85%E7%9A%84%E5%AE%9A%E4%B9%89)
- **K1-7** Workflow 的控制权在代码手里，流程确定、可预测、可复现，但灵活性差；Agent 的控制权在 LLM 手里，行为动态灵活、能适应变化，但带来不确定性。成本上 Workflow 流程固定，token 消耗大约是 Agent 的四分之一；可靠性上 Workflow 出问题容易定位，Agent 决策路径不确定，调试更困难。[原文§核心区别在哪？](https://xiaolinnote.com/agent/concept/agent.html#%E6%A0%B8%E5%BF%83%E5%8C%BA%E5%88%AB%E5%9C%A8%E5%93%AA)
- **K1-8** Anthropic 的建议是从最简单的方案开始，只在明确需要时才增加复杂度：步骤固定、可提前规划或对可靠性要求很高（如金融交易、医疗系统）用 Workflow，任务开放、无法预知所有步骤或需要灵活应对意外用 Agent；生产中最常见的是混合架构，例如客服整体流程用 Workflow 控制，处理环节遇到复杂问题再启动 Agent。[原文§什么时候用 Workflow，什么时候用 Agent？](https://xiaolinnote.com/agent/concept/agent.html#%E4%BB%80%E4%B9%88%E6%97%B6%E5%80%99%E7%94%A8-workflow-%E4%BB%80%E4%B9%88%E6%97%B6%E5%80%99%E7%94%A8-agent)
- **K1-9** ReAct 来自 Reasoning 加 Acting，Agent 在思考和行动之间交替：先思考（Thought）分析当前情况决定下一步，再行动（Action）调用一个工具，然后观察（Observation）工具返回的结果，回到思考直到任务完成。优点是透明可审计、灵活适应、通用性强；缺点是每步都要完整推理一次、token 消耗大，有时会陷入循环反复执行相同动作。[原文§模式一：ReAct（边想边做）](https://xiaolinnote.com/agent/concept/agent.html#%E6%A8%A1%E5%BC%8F%E4%B8%80-react-%E8%BE%B9%E6%83%B3%E8%BE%B9%E5%81%9A)
- **K1-10** 它把工作分成两个阶段：先规划，把完整的执行计划想清楚；再执行，按计划逐步完成，不用每步都重新思考全局。最大的优势是省钱，规划只做一次，token 消耗大约是 ReAct 的五分之一；缺点是不够灵活，执行中情况变了原计划可能不适用，所以有做法是加入重新规划检查点，每隔几步检查计划是否还靠谱。[原文§模式二：Plan-and-Execute（先想好再做）](https://xiaolinnote.com/agent/concept/agent.html#%E6%A8%A1%E5%BC%8F%E4%BA%8C-plan-and-execute-%E5%85%88%E6%83%B3%E5%A5%BD%E5%86%8D%E5%81%9A)
- **K1-11** 反思模式是完成任务后不急着交付、先自我检查一遍。一种是自我反思，同一个 Agent 完成任务后切换到审查者角色审视自己的输出，发现问题就修改再审查；另一种是双 Agent 对话，一个负责生成、另一个负责评审，来回迭代直到评审方满意，适合代码生成、法律文书、学术论文等对质量要求高的场景。[原文§模式三：Reflection（做完再检查）](https://xiaolinnote.com/agent/concept/agent.html#%E6%A8%A1%E5%BC%8F%E4%B8%89-reflection-%E5%81%9A%E5%AE%8C%E5%86%8D%E6%A3%80%E6%9F%A5)
- **K1-12** 让多个专业化的 Agent 各司其职，例如一个负责规划、一个搜集信息、一个写代码、一个测试，通过协作完成复杂任务，主流框架有 LangGraph、CrewAI、OpenAI Agents SDK 和微软的 AutoGen；Anthropic 提醒不要过早引入多 Agent 架构，只有任务确实需要拆成多个并行子任务时才值得引入。[原文§模式四：Multi-Agent（团队协作）](https://xiaolinnote.com/agent/concept/agent.html#%E6%A8%A1%E5%BC%8F%E5%9B%9B-multi-agent-%E5%9B%A2%E9%98%9F%E5%8D%8F%E4%BD%9C)
- **K1-13** 不是，实际中往往组合使用：一个多 Agent 系统里，每个 Agent 内部可能用 ReAct 模式，整体协作用 Multi-Agent 模式，最后还有一个 Reflection 环节检查质量；选哪种模式，关键看任务特点和对灵活性、成本、质量的优先级排序。[原文§模式四：Multi-Agent（团队协作）](https://xiaolinnote.com/agent/concept/agent.html#%E6%A8%A1%E5%BC%8F%E5%9B%9B-multi-agent-%E5%9B%A2%E9%98%9F%E5%8D%8F%E4%BD%9C)
- **K1-14** 它是 OpenAI 在 2023 年 6 月率先推出的能力；在此之前大语言模型只能生成文本，有了它，LLM 不仅能生成文字，还能告诉外部程序“我想调用某个函数，参数是这些”。[原文§从「只会说话」到「能做事情」](https://xiaolinnote.com/agent/concept/agent.html#%E4%BB%8E%E3%80%8C%E5%8F%AA%E4%BC%9A%E8%AF%B4%E8%AF%9D%E3%80%8D%E5%88%B0%E3%80%8C%E8%83%BD%E5%81%9A%E4%BA%8B%E6%83%85%E3%80%8D)
- **K1-15** 第一步定义函数，开发者用 JSON 描述每个函数的名字、功能说明和参数；第二步模型判断，LLM 分析用户意图，决定调用哪个函数并生成参数；第三步执行函数，由应用程序解析指令并实际调用；第四步生成回答，代码把真实结果再发给 LLM，由它用自然语言回复。[原文§Function Call 的工作原理](https://xiaolinnote.com/agent/concept/agent.html#function-call-%E7%9A%84%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86)
- **K1-16** 不是。LLM 只输出“我想调用这个函数，参数是这些”的结构化指令，真正执行函数的是你的应用程序：代码拿到调用指令后解析出参数，去实际调用天气 API 等接口并拿到结果。[原文§Function Call 的工作原理](https://xiaolinnote.com/agent/concept/agent.html#function-call-%E7%9A%84%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86)
- **K1-17** 一是根据用户意图判断是否调用工具、调用哪个；二是从自然语言中提取结构化参数。它让模型的判断能交给应用程序执行，原文因此把它称为 Agent 的技术基石。这里说明的是结构化工具调用的作用。[原文§为什么 Function Call 这么重要？](https://xiaolinnote.com/agent/concept/agent.html#%E4%B8%BA%E4%BB%80%E4%B9%88-function-call-%E8%BF%99%E4%B9%88%E9%87%8D%E8%A6%81)
- **K1-18** 原文用“单步调用”和“循环编排”区分两者：一次 Function Call 请求某个函数及其参数，是一个工具动作；Agent 在执行后观察结果，再决定下一步，可连续组织多次调用完成复杂任务。一次工具动作完成，不等于整个 Agent 任务结束。[原文§Function Call 和 Agent 的关系](https://xiaolinnote.com/agent/concept/agent.html#function-call-%E5%92%8C-agent-%E7%9A%84%E5%85%B3%E7%B3%BB)
- **K1-19** 要为每个服务单独写函数定义和调用逻辑，N 个 AI 应用对接 M 个外部服务就需要 N×M 个定制集成，完全不可扩展；而且各 LLM 厂商的 Function Call 格式不完全一样，OpenAI 用 tool_calls，Anthropic 用 tool_use content block，参数结构也有差异。[原文§Function Call 的集成困境](https://xiaolinnote.com/agent/concept/agent.html#function-call-%E7%9A%84%E9%9B%86%E6%88%90%E5%9B%B0%E5%A2%83)
- **K1-20** Anthropic 在 2024 年 11 月开源了 MCP，全称 Model Context Protocol，即模型上下文协议，可以理解为 AI 界的 USB-C 接口：它提供统一的标准，让任何 AI 应用都能用同一种方式连接任何外部工具和数据源。[原文§MCP 的诞生](https://xiaolinnote.com/agent/concept/agent.html#mcp-%E7%9A%84%E8%AF%9E%E7%94%9F)
- **K1-21** MCP Host 是你使用的 AI 应用，如 Claude Desktop、Cursor 或自己开发的 Agent 应用，是交互的发起方；MCP Client 住在 Host 里，负责跟 MCP Server 通信，像翻译官；MCP Server 对外暴露具体的工具能力和数据资源，例如 GitHub MCP Server 提供搜索代码、创建 Issue、查看 PR 等工具。[原文§MCP 是怎么工作的？](https://xiaolinnote.com/agent/concept/agent.html#mcp-%E6%98%AF%E6%80%8E%E4%B9%88%E5%B7%A5%E4%BD%9C%E7%9A%84)
- **K1-22** 用户在 AI 应用中提问，AI 应用（Host）通过 MCP Client 发现有哪些可用工具，AI 决定调用某个工具，MCP Client 向对应的 MCP Server 发送请求，Server 执行操作并返回结果，AI 再基于结果生成回答。[原文§MCP 是怎么工作的？](https://xiaolinnote.com/agent/concept/agent.html#mcp-%E6%98%AF%E6%80%8E%E4%B9%88%E5%B7%A5%E4%BD%9C%E7%9A%84)
- **K1-23** 每个 AI 应用只要实现一次 Client，每个服务只要提供一个 MCP Server，双方就能自动对接；MCP Server 暴露的工具是可发现的，AI 应用启动时能自动查询有哪些 Server、每个 Server 提供哪些工具、每个工具的参数是什么，因此 Agent 可以在运行时动态发现新能力，而不是只能用开发者写死的函数。[原文§MCP 解决了什么问题？](https://xiaolinnote.com/agent/concept/agent.html#mcp-%E8%A7%A3%E5%86%B3%E4%BA%86%E4%BB%80%E4%B9%88%E9%97%AE%E9%A2%98)
- **K1-24** Skills 是一种自然语言指令文件，通常是 Markdown 格式，教 Agent 在什么场景下、按什么方法、遵循什么规范完成特定任务，在 Claude Code、Cursor 等工具里通常以 SKILL.md 存在；顶部是一段 YAML 元数据，声明这个 Skill 什么时候应该被激活，下面是用自然语言写的具体行为指令。[原文§Skills 是什么？](https://xiaolinnote.com/agent/concept/agent.html#skills-%E6%98%AF%E4%BB%80%E4%B9%88-1)
- **K1-25** MCP 给了 Agent 一个装满工具的厨房，解决的是能做什么的问题；Skills 是一本菜谱，解决的是该怎么做的问题；一个完整的 Agent 两者都需要。[原文§Skills 是什么？](https://xiaolinnote.com/agent/concept/agent.html#skills-%E6%98%AF%E4%BB%80%E4%B9%88-1)
- **K1-26** Agent 启动时扫描可用的 Skills 列表；用户提出请求时，Agent 判断有没有匹配的 Skill，如果有，就把这个 Skill 的内容加载到上下文中，然后按照 Skill 里的指令来思考和行动。[原文§Skills 的工作方式](https://xiaolinnote.com/agent/concept/agent.html#skills-%E7%9A%84%E5%B7%A5%E4%BD%9C%E6%96%B9%E5%BC%8F)
- **K1-27** 不只是。Skill 的本质是知识加行为指令：它可以在 SKILL.md 里用 allowed-tools 字段声明需要使用的工具（如 Bash、Read、Edit），可以打包可执行的脚本文件，还可以指导 Agent 去调用 MCP 工具或发起 Function Call，例如部署 Skill 声明 allowed-tools: Bash 后按步骤执行测试、构建和部署脚本。[原文§Skills 的工作方式](https://xiaolinnote.com/agent/concept/agent.html#skills-%E7%9A%84%E5%B7%A5%E4%BD%9C%E6%96%B9%E5%BC%8F)
- **K1-28** 把专业知识和最佳实践编码成可复用的模块，例如代码审查 Skill 定义审查流程、关注点和输出格式，SQL 优化 Skill 编码 DBA 的优化经验；这些经验以前在人的脑子里，现在可以写成 Skill 文件让 Agent 使用，而且可以共享复用，团队里所有人的 Agent 都能用上。[原文§Skills 有什么价值？](https://xiaolinnote.com/agent/concept/agent.html#skills-%E6%9C%89%E4%BB%80%E4%B9%88%E4%BB%B7%E5%80%BC)
- **K1-29** Function Call 解决 LLM 怎么跟外部函数交互，是一种 API 协议，LLM 输出结构化调用请求、应用程序执行后返回结果；MCP 解决怎么用统一标准管理大量工具，是一种通信标准，定义 Client 和 Server 如何发现和调用工具；Skills 解决 Agent 怎么获得领域专业知识，是一种提示词扩展，把自然语言行为指令加载到上下文。[原文§三者的本质区别](https://xiaolinnote.com/agent/concept/agent.html#%E4%B8%89%E8%80%85%E7%9A%84%E6%9C%AC%E8%B4%A8%E5%8C%BA%E5%88%AB)
- **K1-30** 运行位置上，Function Call 的函数在你的应用程序中执行，MCP 的工具在外部的 MCP Server 中执行，Skills 在 Agent 的上下文窗口内生效；标准化程度上，Function Call 在各 LLM 厂商之间格式不统一，MCP 是统一的开放标准、跨厂商通用，Skills 目前还没有统一标准，各 Agent 平台有自己的格式。[原文§三者的本质区别](https://xiaolinnote.com/agent/concept/agent.html#%E4%B8%89%E8%80%85%E7%9A%84%E6%9C%AC%E8%B4%A8%E5%8C%BA%E5%88%AB)
- **K1-31** 三者不是竞争而是分层互补：Function Call 是底层基础；MCP 建立在 Function Call 之上提供标准化包装，通过 MCP 调用工具时底层仍在做 Function Call，只是格式和通信方式被统一了；Skills 在另一个维度上工作，不参与工具调用过程，而是指导 Agent 什么时候该调用工具、用什么策略完成任务。[原文§三者是什么关系？](https://xiaolinnote.com/agent/concept/agent.html#%E4%B8%89%E8%80%85%E6%98%AF%E4%BB%80%E4%B9%88%E5%85%B3%E7%B3%BB)
- **K1-32** 企业里的多个 Agent 可能由不同团队用不同框架开发，协作时互相不认识，也不知道对方会什么、怎么沟通；MCP 是给 Agent 连接工具用的，处理的是 Agent 调用数据库、发送邮件这类 Agent 与工具之间的交互，Agent 与 Agent 之间的协作需要一个全新的协议。[原文§为什么需要 A2A？](https://xiaolinnote.com/agent/concept/agent.html#%E4%B8%BA%E4%BB%80%E4%B9%88%E9%9C%80%E8%A6%81-a2a)
- **K1-33** A2A 全称 Agent-to-Agent Protocol，是 Google 在 2025 年 4 月的 Google Cloud Next 大会上发布的开放协议，联合了 Atlassian、Salesforce、SAP、MongoDB、LangChain 等超过 50 家合作伙伴；它定义了一套标准，让不同的 AI Agent 能互相发现、互相通信、互相委派任务，不管用什么框架开发、运行在什么平台上。[原文§A2A 是什么？](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E6%98%AF%E4%BB%80%E4%B9%88)
- **K1-34** Agent 之间用消息沟通过程中的信息，用制品传递最终结果，例如研究 Agent 完成分析后，把报告作为制品返回给请求方。[原文§A2A 的核心概念](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E6%A0%B8%E5%BF%83%E6%A6%82%E5%BF%B5)
- **K1-35** 每个支持 A2A 的 Agent 都会发布一个 JSON 格式的名片，描述自己的身份、能力、擅长的领域、支持的交互方式、认证要求等信息；其他 Agent 通过读取这个名片来了解这个 Agent 会什么、能请它帮什么忙。[原文§A2A 的核心概念](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E6%A0%B8%E5%BF%83%E6%A6%82%E5%BF%B5)
- **K1-36** A2A 的所有协作都围绕任务展开：一个 Client Agent 作为发起方创建任务，发送给作为执行方的 Remote Agent；任务有完整的生命周期，从创建、处理中到完成或失败，每个状态变化都有明确定义，让双方能清楚地跟踪任务进展。[原文§A2A 的核心概念](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E6%A0%B8%E5%BF%83%E6%A6%82%E5%BF%B5)
- **K1-37** MCP 是竖向的，处理 Agent 到工具的连接；A2A 是横向的，处理 Agent 到 Agent 的协作。两者互补、可以共同使用：典型的多 Agent 系统里，编排 Agent 通过 A2A 把任务委派给不同的专业 Agent，每个专业 Agent 内部再通过 MCP 连接自己需要的工具。[原文§A2A 和 MCP 是什么关系？](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E5%92%8C-mcp-%E6%98%AF%E4%BB%80%E4%B9%88%E5%85%B3%E7%B3%BB)
- **K1-38** A2A 是模态无关的：除了文本，还能交换音频、视频、图像和结构化数据等格式。[原文§A2A 的技术特点](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E6%8A%80%E6%9C%AF%E7%89%B9%E7%82%B9)
- **K1-39** A2A 支持异步和长时间运行的任务，并提供任务状态查询、进度更新和断线重连。[原文§A2A 的技术特点](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E6%8A%80%E6%9C%AF%E7%89%B9%E7%82%B9)
- **K1-40** 它完全基于现有的 Web 标准：HTTP 用于传输，JSON 用于消息格式，SSE 用于实时流式通信；这意味着不需要引入任何新的基础设施，现有的 Web 技术栈就能直接支持。[原文§A2A 的技术特点](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E6%8A%80%E6%9C%AF%E7%89%B9%E7%82%B9)
- **K1-41** 截至 2026 年初 A2A 还处于发展早期，远不如 MCP 那样已成为事实标准，但它填补了 MCP 明确不处理的 Agent 间协作空白，业界普遍看好；整个协议生态正形成清晰分层：Function Call 提供底层调用能力，MCP 标准化 Agent 与工具的连接，A2A 标准化 Agent 与 Agent 的协作。[原文§A2A 的生态现状](https://xiaolinnote.com/agent/concept/agent.html#a2a-%E7%9A%84%E7%94%9F%E6%80%81%E7%8E%B0%E7%8A%B6)

## 2. OpenClaw 的系统组成与运行方式

原文：[OpenClaw 是什么？OpenClaw 面试题万字图解](https://xiaolinnote.com/agent/concept/openclaw.html)。

- **K2-1** Gateway 是所有消息的入口，负责身份鉴权、管理会话状态，并把请求路由给处理它的组件；Agent 是任务执行框架，调用大模型、把想法拆成执行计划、协调工具，并跟进进度和汇报结果。[原文§1、什么是 OpenClaw？](https://xiaolinnote.com/agent/concept/openclaw.html#_1%E3%80%81%E4%BB%80%E4%B9%88%E6%98%AF-openclaw)
- **K2-2** Channels 把飞书、微信、Telegram 等平台各不相同的消息转成 AI 能理解的统一内容，再把 AI 的回复转成对应平台能发出的格式，并一直保持连线。[原文§1、什么是 OpenClaw？](https://xiaolinnote.com/agent/concept/openclaw.html#_1%E3%80%81%E4%BB%80%E4%B9%88%E6%98%AF-openclaw)
- **K2-3** Nodes 是运行在手机、笔记本、台式机等设备上的小节点，为智能体提供摄像头、地理位置、屏幕渲染或系统控制等本地高权限能力；Tools 则是开文件、发邮件、调接口这类单个基础工具。[原文§1、什么是 OpenClaw？](https://xiaolinnote.com/agent/concept/openclaw.html#_1%E3%80%81%E4%BB%80%E4%B9%88%E6%98%AF-openclaw)
- **K2-4** 大语言模型是无状态的对话系统，只在给定的上下文里回答，对话一结束什么都不会留下；它像一个有超级大脑但没有身体的人，OpenClaw 给这个大脑配上完整的身体：有手脚去操作电脑和设备，有记忆记住偏好和历史，有眼睛感知环境，有通讯工具接入日常用的消息平台。[原文§1、什么是 OpenClaw？](https://xiaolinnote.com/agent/concept/openclaw.html#_1%E3%80%81%E4%BB%80%E4%B9%88%E6%98%AF-openclaw)
- **K2-5** Tools 是单个的基础小工具，比如开一个本地文件、发一封邮件、调一个软件接口；Skills 是把好几个工具串起来的一套完整干活流程，比如“整理项目周报”这个技能，就是把读邮件、拉进度、写文档、发提醒串起来的一套活。[原文§1、什么是 OpenClaw？](https://xiaolinnote.com/agent/concept/openclaw.html#_1%E3%80%81%E4%BB%80%E4%B9%88%E6%98%AF-openclaw)
- **K2-6** 原文的理由是有价值的内容会被提炼后写进本地文件，所以称它是真正的永久记忆，记忆不会丢。[原文§2、OpenClaw 核心亮点是什么？](https://xiaolinnote.com/agent/concept/openclaw.html#_2%E3%80%81openclaw-%E6%A0%B8%E5%BF%83%E4%BA%AE%E7%82%B9%E6%98%AF%E4%BB%80%E4%B9%88)
- **K2-7** 多平台打通是通过网关组件直接连飞书、钉钉、微信等通讯软件，在这些软件里发消息就能指挥家里电脑上跑着的 OpenClaw，结果再发回给你；权限超大是配合底层的终端节点，它能直接操作电脑的文件、运行命令行、控制浏览器甚至操作桌面应用。[原文§2、OpenClaw 核心亮点是什么？](https://xiaolinnote.com/agent/concept/openclaw.html#_2%E3%80%81openclaw-%E6%A0%B8%E5%BF%83%E4%BA%AE%E7%82%B9%E6%98%AF%E4%BB%80%E4%B9%88)
- **K2-8** 它每 30 分钟会自动跑一次心跳文档，主动自检、主动做事，还支持自定义定时任务，不用人守着就能在后台运行。[原文§2、OpenClaw 核心亮点是什么？](https://xiaolinnote.com/agent/concept/openclaw.html#_2%E3%80%81openclaw-%E6%A0%B8%E5%BF%83%E4%BA%AE%E7%82%B9%E6%98%AF%E4%BB%80%E4%B9%88)
- **K2-9** 当你指出某个操作出错，或它自己执行时踩了坑，它会调整方案重试，并在当前任务执行循环里启动反思环节，把失败原因、正确的操作逻辑和需要规避的问题总结成可复用的避坑经验，明文写入本地的长期记忆文件；之后执行同类任务时，系统自动把这些经验加载到提示词上下文里。[原文§2、OpenClaw 核心亮点是什么？](https://xiaolinnote.com/agent/concept/openclaw.html#_2%E3%80%81openclaw-%E6%A0%B8%E5%BF%83%E4%BA%AE%E7%82%B9%E6%98%AF%E4%BB%80%E4%B9%88)
- **K2-10** 大模型本身只懂生成文本，有了庞大的技能生态，加能力非常简单：一句话就能装上新的插件，不用复杂配置；装上对应的技能包，它就能掌握读写邮件或查阅全网资讯等能力。[原文§2、OpenClaw 核心亮点是什么？](https://xiaolinnote.com/agent/concept/openclaw.html#_2%E3%80%81openclaw-%E6%A0%B8%E5%BF%83%E4%BA%AE%E7%82%B9%E6%98%AF%E4%BB%80%E4%B9%88)
- **K2-11** 原文称 SOUL.md 是个性化的系统提示词，定义价值观、语气和幽默感，决定它怎么说话；AGENTS.md 是操作手册，记录处理任务时必须遵守的标准流程，决定它怎么做事。[原文§3、OpenClaw 文件目录结构是怎样的？](https://xiaolinnote.com/agent/concept/openclaw.html#_3%E3%80%81openclaw-%E6%96%87%E4%BB%B6%E7%9B%AE%E5%BD%95%E7%BB%93%E6%9E%84%E6%98%AF%E6%80%8E%E6%A0%B7%E7%9A%84)
- **K2-12** TOOLS.md 注册了智能体可用的全部本地工具和技能，AI 执行任务前会先查看它。[原文§3、OpenClaw 文件目录结构是怎样的？](https://xiaolinnote.com/agent/concept/openclaw.html#_3%E3%80%81openclaw-%E6%96%87%E4%BB%B6%E7%9B%AE%E5%BD%95%E7%BB%93%E6%9E%84%E6%98%AF%E6%80%8E%E6%A0%B7%E7%9A%84)
- **K2-13** HEARTBEAT.md 是日常巡检的任务清单，心跳时间一到，系统会优先读取它。[原文§3、OpenClaw 文件目录结构是怎样的？](https://xiaolinnote.com/agent/concept/openclaw.html#_3%E3%80%81openclaw-%E6%96%87%E4%BB%B6%E7%9B%AE%E5%BD%95%E7%BB%93%E6%9E%84%E6%98%AF%E6%80%8E%E6%A0%B7%E7%9A%84)
- **K2-14** OpenClaw 的智能体本质上就是一个普通的文件夹，即名为 openclaw-workspace 的工作空间目录，想把调教好的智能体分享给同事，直接把文件夹打包发过去就行；其中 MEMORY.md 存放提炼后的长期记忆和事实偏好，sessions 文件夹按天存放短期对话流水账。[原文§3、OpenClaw 文件目录结构是怎样的？](https://xiaolinnote.com/agent/concept/openclaw.html#_3%E3%80%81openclaw-%E6%96%87%E4%BB%B6%E7%9B%AE%E5%BD%95%E7%BB%93%E6%9E%84%E6%98%AF%E6%80%8E%E6%A0%B7%E7%9A%84)
- **K2-15** 原文依靠设备上的常驻守护进程与心跳保持任务运行，Gateway 接收和路由请求，Channels 保持聊天平台连接并转换消息，因此锁屏或关闭聊天界面后仍可接收指令。这是部署与连接机制带来的能力，并非仅有 Agent 执行闭环就天然具备。[原文§1、什么是 OpenClaw？](https://xiaolinnote.com/agent/concept/openclaw.html#_1%E3%80%81%E4%BB%80%E4%B9%88%E6%98%AF-openclaw) [原文§4、OpenClaw 与传统的 Agent 有什么区别？](https://xiaolinnote.com/agent/concept/openclaw.html#_4%E3%80%81openclaw-%E4%B8%8E%E4%BC%A0%E7%BB%9F%E7%9A%84-agent-%E6%9C%89%E4%BB%80%E4%B9%88%E5%8C%BA%E5%88%AB)
- **K2-16** 原文的对比是：传统 Agent 的记忆存在云端，是用户插不上手的黑盒；OpenClaw 的记忆是本地纯文本文件，全透明可控，可以随时打开修改、删减，甚至做版本管理。[原文§4、OpenClaw 与传统的 Agent 有什么区别？](https://xiaolinnote.com/agent/concept/openclaw.html#_4%E3%80%81openclaw-%E4%B8%8E%E4%BC%A0%E7%BB%9F%E7%9A%84-agent-%E6%9C%89%E4%BB%80%E4%B9%88%E5%8C%BA%E5%88%AB)
- **K2-17** 传统 Agent 活在云端的虚拟沙盒里，碰不到电脑里的真实文件，往往只能写段代码让你自己去跑；OpenClaw 本地优先，直接跑在你的设备上，能操作本地文件、执行终端命令、操控软件。传统 Agent 多是针对特定场景的特定工具，OpenClaw 是通用的 AI 执行网关，大模型可切换，入口对接微信或飞书，能力靠技能插件扩展。[原文§4、OpenClaw 与传统的 Agent 有什么区别？](https://xiaolinnote.com/agent/concept/openclaw.html#_4%E3%80%81openclaw-%E4%B8%8E%E4%BC%A0%E7%BB%9F%E7%9A%84-agent-%E6%9C%89%E4%BB%80%E4%B9%88%E5%8C%BA%E5%88%AB)
- **K2-18** 人类可读的记忆留在 Markdown 文件里，SQLite 只作高速缓存索引：MEMORY.md 写入新内容后，系统把新增文本切块、转成向量再存入。[原文§5、OpenClaw 的记忆化机制是怎么实现的？](https://xiaolinnote.com/agent/concept/openclaw.html#_5%E3%80%81openclaw-%E7%9A%84%E8%AE%B0%E5%BF%86%E5%8C%96%E6%9C%BA%E5%88%B6%E6%98%AF%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E7%9A%84)
- **K2-19** 当系统发现聊天记录越来越长、快要触发上下文压缩时，会在后台拦截，强制大模型做一次阅读理解，把刚才聊天里最重要的事实或新学到的知识提炼出来，直接写入外层的 MEMORY.md 长期记忆文件。[原文§5、OpenClaw 的记忆化机制是怎么实现的？](https://xiaolinnote.com/agent/concept/openclaw.html#_5%E3%80%81openclaw-%E7%9A%84%E8%AE%B0%E5%BF%86%E5%8C%96%E6%9C%BA%E5%88%B6%E6%98%AF%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E7%9A%84)
- **K2-20** 不把几万字的记忆文件全塞给大模型，而是把当前问题也转换成向量，在 SQLite 里做向量相似度比对，同时结合 BM25 算法做关键词匹配；通过这种双路召回，把最相关的那几句话捞出来，重新塞回给大模型作为背景知识。[原文§5、OpenClaw 的记忆化机制是怎么实现的？](https://xiaolinnote.com/agent/concept/openclaw.html#_5%E3%80%81openclaw-%E7%9A%84%E8%AE%B0%E5%BF%86%E5%8C%96%E6%9C%BA%E5%88%B6%E6%98%AF%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E7%9A%84)
- **K2-21** 不需要去折腾数据库，直接用电脑自带的记事本打开 MEMORY.md，把写错的那行字删掉保存即可。[原文§5、OpenClaw 的记忆化机制是怎么实现的？](https://xiaolinnote.com/agent/concept/openclaw.html#_5%E3%80%81openclaw-%E7%9A%84%E8%AE%B0%E5%BF%86%E5%8C%96%E6%9C%BA%E5%88%B6%E6%98%AF%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E7%9A%84)
- **K2-22** 一是云端智能体无法落地执行的割裂感，它写完代码自己在本地运行测试、看日志修复，完成最后一公里闭环；二是长期使用的失忆问题，它把你的偏好、习惯和项目进度记在本地硬盘上；三是工具切换的繁琐，它通过网关把 AI 接进即时通讯软件，在聊天框里发消息就能让它干活。[原文§6、OpenClaw 到底解决了什么痛点？](https://xiaolinnote.com/agent/concept/openclaw.html#_6%E3%80%81openclaw-%E5%88%B0%E5%BA%95%E8%A7%A3%E5%86%B3%E4%BA%86%E4%BB%80%E4%B9%88%E7%97%9B%E7%82%B9)
- **K2-23** 它强依赖设备在线：设备关机或断网后心跳失效，也收不到远程指令。[原文§7、OpenClaw 有什么缺点？](https://xiaolinnote.com/agent/concept/openclaw.html#_7%E3%80%81openclaw-%E6%9C%89%E4%BB%80%E4%B9%88%E7%BC%BA%E7%82%B9)
- **K2-24** 不是。OpenClaw 运行在本地设备上，但仍要请求大模型接口并消耗 Token。[原文§7、OpenClaw 有什么缺点？](https://xiaolinnote.com/agent/concept/openclaw.html#_7%E3%80%81openclaw-%E6%9C%89%E4%BB%80%E4%B9%88%E7%BC%BA%E7%82%B9)
- **K2-25** 它被允许随意读写本地文件、执行系统级终端命令，一旦底层大模型产生幻觉，或接入外网时遭遇提示词注入攻击，就可能执行危险的删除命令或把私钥文件发到公共网络；因此在生产环境部署时，必须谨慎地设置沙箱隔离和严格的工具使用边界。[原文§7、OpenClaw 有什么缺点？](https://xiaolinnote.com/agent/concept/openclaw.html#_7%E3%80%81openclaw-%E6%9C%89%E4%BB%80%E4%B9%88%E7%BC%BA%E7%82%B9)
- **K2-26** 原文的对比是：Coze 的数据和权限都在云端，碰不到本地文件；n8n 按触发器和条件执行固定流程，没有自主思考能力；OpenClaw 能自己规划步骤，并拥有本地系统的操作权限。[原文§8、Coze、n8n 和 OpenClaw 的区别在哪里？](https://xiaolinnote.com/agent/concept/openclaw.html#_8%E3%80%81coze%E3%80%81n8n-%E5%92%8C-openclaw-%E7%9A%84%E5%8C%BA%E5%88%AB%E5%9C%A8%E5%93%AA%E9%87%8C)
- **K2-27** token 是大模型的计费单位，你对大模型说的每一句话和它回的每一句话都会拆成一个个 token 来算钱；1 个 token 差不多是半个汉字，话越长，花的 token 越多。[原文§9. 为什么 OpenClaw 那么烧 token？](https://xiaolinnote.com/agent/concept/openclaw.html#_9-%E4%B8%BA%E4%BB%80%E4%B9%88-openclaw-%E9%82%A3%E4%B9%88%E7%83%A7-token)
- **K2-28** 它是全天候待命的守护进程，假设每半小时心跳一次，一天就要自动唤醒四十八次；每次唤醒系统都要把人物设定、操作规范、可用工具清单和心跳任务大纲组装成一段巨大的提示词发给云端大模型，哪怕什么异常都没发生，也在消耗大量输入 Token。[原文§9. 为什么 OpenClaw 那么烧 token？](https://xiaolinnote.com/agent/concept/openclaw.html#_9-%E4%B8%BA%E4%BB%80%E4%B9%88-openclaw-%E9%82%A3%E4%B9%88%E7%83%A7-token)
- **K2-29** 自主试错：命令行报错时它会把长长的报错日志读进去、分析原因、生成新方案再执行，循环往复不断累积上下文；记忆压缩：短期日志快触碰上下文极限时，后台拉起独立的总结任务，让大模型阅读大量聊天记录并提炼写入长期记忆，后续还要把召回的记忆塞回提示词；系统提示词沉重：性格文件、操作手册和工具清单每次处理任务都要全文带上。[原文§9. 为什么 OpenClaw 那么烧 token？](https://xiaolinnote.com/agent/concept/openclaw.html#_9-%E4%B8%BA%E4%BB%80%E4%B9%88-openclaw-%E9%82%A3%E4%B9%88%E7%83%A7-token)
