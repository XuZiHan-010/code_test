### docker底层依托于linux怎么实现资源隔离的？

- **Y1-1** 2 个空是 Namespace（命名空间）、cgroups（顺序不限）。Namespace 负责视图隔离，cgroups 负责资源隔离。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)
- **Y1-2** Namespace（命名空间）。每个容器都运行在自己的一组命名空间中，以此实现容器之间的视图隔离。cgroups 管的是 CPU、内存、磁盘 I/O 等资源的分配与限制；UnionFS 是镜像分层的底层；Hypervisor 是虚拟机用来模拟硬件的，都不是视图隔离的机制。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)
- **Y1-3** cgroups。它是 Linux 内核的一个功能，允许在进程组之间分配、限制和优先处理系统资源。Namespace 做的是视图隔离，不管资源配额；写时复制和 UnionFS 属于镜像分层与容器可写层的机制，答非所问。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)
- **Y1-4** 正确的是 PID（进程）、网络、挂载点和 IPC（进程间通信）。原文说每个容器都运行在自己的一组命名空间中，包括这些内容。CPU 与内存的使用上限是 cgroups 做的资源限制，镜像的只读分层结构是镜像分层原理，都不是命名空间所隔离的内容。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)
- **Y1-5** 在题设独立、未与其他容器共享且未在其中创建子 PID 命名空间的情况下，只能看到该命名空间中的进程，看不到宿主机或其他独立容器的进程；可见性不按镜像划分。（原文据此进一步概括为“因此也不会影响其他容器中的进程”；视图隔离不能推出任意资源和配置下都互不影响。）[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84) [核对来源：pid_namespaces(7)](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html)
- **Y1-6** cgroups 是 Linux 内核的一个功能，允许在进程组之间分配、限制和优先处理系统资源，如 CPU、内存和磁盘 I/O。把镜像按层存储的是存储驱动，让容器只看到自己空间内进程的是命名空间，存储和分发镜像的是仓库，都不是 cgroups。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)
- **Y1-7** 正确的是 CPU、内存和磁盘 I/O。挂载点和 IPC 的可见范围属于命名空间做的视图隔离，不是 cgroups 管理的资源。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)

- **Y1-9** Namespace 负责基于视图的隔离，cgroups 负责资源隔离。把两者分工说反、或说成都只做视图隔离、或把 Namespace 当成镜像分层存储，都不是原文的说法。[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84)
- **Y1-10** Docker 依托 Linux 的两项机制。一是 Namespace：默认容器分别使用隔离的命名空间，包括 PID（进程）、网络、挂载点、IPC（进程间通信）等；未与其他容器共享、也未在其中创建子 PID 命名空间时，容器只看到自身 PID 命名空间中的进程，这是视图隔离。二是 cgroups：它是 Linux 内核的一个功能，允许在进程组之间分配、限制和优先处理 CPU、内存和磁盘 I/O 等系统资源，有助于资源限制、工作负载隔离以及在不同进程组之间进行资源优先处理，这是资源隔离。（原文将视图隔离概括为“不会影响其他容器中的进程”；若显式共享命名空间或数据卷，仍可能相互影响。）[原文§docker底层依托于linux怎么实现资源隔离的？](https://xiaolincoding.com/interview/docker.html#docker%E5%BA%95%E5%B1%82%E4%BE%9D%E6%89%98%E4%BA%8Elinux%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E8%B5%84%E6%BA%90%E9%9A%94%E7%A6%BB%E7%9A%84) [核对来源：pid_namespaces(7)](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html) [核对来源：Docker Volumes](https://docs.docker.com/engine/storage/volumes/)

### 讲讲cgroup v2.0
