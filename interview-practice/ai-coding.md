# AI 编程专题面试题

来源：[小林面试笔记 AI 编程专题](https://xiaolinnote.com/ai/coding/coding_info.html)。题目按原专题 4 篇文章逐篇覆盖，只考原文讲到的内容；每个编号只考一个主要问题。题号前缀为 `P`。

## 1. 大型仓库中的代码定位

- **P1-1** Coding Agent 在大型仓库里定位相关代码，核心思路是什么？
- **P1-2** 为什么命中了文件，还不一定找到了相关实现？
- **P1-3** 代码定位的结果通常是什么形态？
- **P1-4** 定位代码时，为什么要确认代码版本？
- **P1-5** 什么是搜索锚点，为什么不直接拿需求原话去搜？
- **P1-6** 面对陌生仓库，怎样确定搜索范围？
- **P1-7** 为什么说搜索是一个反复进行的过程？
- **P1-8** 文本搜索、语义检索和符号工具各适合什么情况？
- **P1-9** 为什么同名的文本不能当成同一个实现？
- **P1-10** 确认符号之后，应该怎样展开阅读？
- **P1-11** 语法解析器能做什么，不能做什么？
- **P1-12** 读懂一个函数之后，还要沿哪些关系继续查找？
- **P1-13** 找到了类或函数，为什么还要核对注册与配置？
- **P1-14** 查找引用没有结果，就能排除这个候选吗？扩展关系时怎样避免读得太多？
- **P1-15** 怎样判断代码已经定位到位？
- **P1-16** 工具结果不完整时，定位结论要注意什么？
- **P1-17** 定位完成后，上下文里应该保留什么？

## 2. 过期的代码描述

- **P2-1** Coding Agent 怎样避免被过期的代码描述误导？
- **P2-2** 代码描述为什么会过期，哪种过期最难发现？
- **P2-3** 能用生成时间判断一条描述是否过期吗？
- **P2-4** 一条可维护的代码描述要记录哪些来源信息？
- **P2-5** 内容指纹起什么作用，它的范围应该怎么定？
- **P2-6** 仓库有了新提交，所有描述都要重写吗？“失效”又是什么意思？
- **P2-7** 文件本身没改，它的描述为什么也可能失效？
- **P2-8** 代码变更后，怎样确定哪些描述需要重新检查？
- **P2-9** 依赖检查的粒度怎么选？
- **P2-10** 发现源码变化后，为什么要先让旧描述失效，再去重建？
- **P2-11** 怎样防止迟到的旧生成任务覆盖较新的描述？
- **P2-12** 固定提交和正在编辑的工作区，描述更新分别怎么处理？
- **P2-13** 描述对应的输入没变，是否就可以直接相信？
- **P2-14** 发现描述与当前实现冲突时怎么处理？
- **P2-15** 检索端停用了旧描述，Agent 这边还需要做什么？

## 3. AI 生成代码的质量

- **P3-1** 判断 AI 生成的代码能不能交付，主要看什么？
- **P3-2** 代码能编译、能运行，为什么还不够？
- **P3-3** 除了新功能是否正确，质量还包括哪些方面？
- **P3-4** 生成之前需要先确定哪些约束？
- **P3-5** 为什么还要给模型提供项目上下文并限定修改范围？
- **P3-6** 为什么测试的预期不能照着生成的实现来写？
- **P3-7** 什么是测试 Oracle？
- **P3-8** 断言应该观察什么？
- **P3-9** 构建与类型检查、静态分析、单元测试各能发现什么问题？
- **P3-10** 为什么还需要集成验证，测试替身有什么局限？
- **P3-11** 回归测试要注意什么，验证强度怎样确定？
- **P3-12** 检查都通过了，为什么还要审查实际的 Diff？
- **P3-13** 审查时为什么要特别看测试和检查配置本身的改动？
- **P3-14** Diff 审查还要关注哪些自动检查难以判断的方面？
- **P3-15** 验证失败之后，应该怎样判断改哪里？
- **P3-16** 修复之后怎样才算完成，交付时要说明什么？

## 4. AI 生成测试的业务覆盖

- **P4-1** 怎样保证 AI 生成的测试用例覆盖关键业务场景？
- **P4-2** 为什么测试数量多不代表业务覆盖好？
- **P4-3** 为什么代码覆盖率也不能代表业务覆盖？
- **P4-4** 业务规则和测试场景是什么关系？
- **P4-5** 怎样从一条范围校验规则推导出测试场景？
- **P4-6** 带状态、带权限的业务还要推导哪些场景？
- **P4-7** 跨步骤流程、重复操作和并发要考虑哪些场景？
- **P4-8** 条件组合很多时，怎样取舍？
- **P4-9** 怎样保证一条测试真的触发了它声称要测的场景？
- **P4-10** 用测试替身制造依赖失败时要注意什么？
- **P4-11** 并发和异步场景的测试怎样写才可靠？
- **P4-12** 测试预期应该从哪里来，参考模型有什么要求？
- **P4-13** 断言怎样才算检验了业务规则？
- **P4-14** 怎样找出已有测试的覆盖缺口？
- **P4-15** 对重要规则，怎样检验测试真的能发现错误？
- **P4-16** 什么是变异测试，结果应该怎样解读？
- **P4-17** 在这套流程里，AI 和开发者各负责什么？
