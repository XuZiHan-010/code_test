O4-14 [single] 按原文，appendfsync 的 Always 策略有什么特点？

O4-28 [short] Redis有哪些持久化方式？分别的优缺点是什么？

Answer (L374): Redis 的读写都在内存中，重启后数据会丢失，所以提供持久化把数据存到磁盘。主要有 AOF 和 RDB 两种，也可以使用混合持久化：AOF 日志是每执行一条写命令就以追加方式写入文件，重启时读取并逐一执行命令恢复，可通过 appendfsync 的 always、everysec、no 取舍安全性和性能；RDB 快照是将某一时刻的内存数据以二进制方式写入磁盘，用 save（在主线程执行，会阻塞）或 bgsave（fork 子进程生成，但 fork 本身仍会短暂阻塞主线程）生成，恢复时直接加载，通常比重放 AOF 快；混合持久化是 Redis 4.0 新增的，开启后 AOF 重写的基础数据采用 RDB 格式，后续变化采用 AOF 命令格式，恢复时先加载基础数据再回放增量命令。AOF 的优点是刷盘策略可选、everysec 通常保留更多近期写入、可后台重写压缩，缺点是文件通常比 RDB 大、恢复耗时可能更长、write/always 的 fsync/重写时的 fork 会带来延迟、损坏修复可能截掉部分数据；RDB 的优点是文件紧凑便于备份传输、恢复通常更快、BGSAVE 主要在子进程写，缺点是可能丢失最近一次快照之后的修改、fork 短暂阻塞、写入频繁时写时复制增加内存占用。如果只是可重建的缓存，可按恢复成本决定是否持久化；不能轻易重建的数据则要结合允许的丢失范围，选择持久化、备份和复制方案，不能只看性能。[原文§Redis有哪些持久化方式？分别的优缺点是什么？](https://xiaolincoding.com/interview/redis.html#redis%E6%9C%89%E5%93%AA%E4%BA%9B%E6%8C%81%E4%B9%85%E5%8C%96%E6%96%B9%E5%BC%8F-%E5%88%86%E5%88%AB%E7%9A%84%E4%BC%98%E7%BC%BA%E7%82%B9%E6%98%AF%E4%BB%80%E4%B9%88)

O4-39 [short] AOF 重写是怎么实现的？

Answer (L388): AOF 一直追加写命令，文件会越来越大，但恢复当前数据不需要重放所有历史操作，所以提供 AOF 重写：例如先 SET counter 0 再 INCR 100 次，重写时只需生成能恢复“counter 等于 100”的数据。AOF 重写是根据当前内存数据生成新的持久化内容，不是读取旧 AOF 再逐条合并命令，可用 BGREWRITEAOF 手动触发，也可根据文件大小和增长比例自动触发。重写由子进程完成，主进程继续处理请求。重写期间的新写入要区分版本：Redis 7.0 之前，主进程继续写原 AOF，同时把增量写入保存到 AOF 重写缓冲区，最后补到新文件再切换；Redis 7.0 起使用多部分 AOF，子进程生成新的 base 文件，主进程把重写期间的变化写到新的 incr 文件，完成后通过 manifest 切换，减少了重写缓冲区和补写的开销。开启混合持久化时 base 采用 RDB 格式，否则采用 AOF 命令格式；无论哪种，都要关注 fork、写时复制、磁盘空间和子进程 I/O。[原文§AOF 重写是怎么实现的？](https://xiaolincoding.com/interview/redis.html#aof-%E9%87%8D%E5%86%99%E6%98%AF%E6%80%8E%E4%B9%88%E5%AE%9E%E7%8E%B0%E7%9A%84)

O4-55 [short] 同时开启 RDB 和 AOF，重启时加载哪个？

Answer (L410): 正常情况下，开启 AOF 后 Redis 重启会优先使用 AOF 恢复数据，因为它通常比独立的 RDB 快照保留更多近期变化，而不是把 dump.rdb 和 AOF 各加载一次。如果使用混合持久化，AOF 的基础部分本身可能就是 RDB 格式，恢复时先加载这部分，再回放后面的增量命令；Redis 7.0 的多部分 AOF 则按照 manifest 指定的 base 和 incr 文件顺序恢复。如果 AOF 损坏，不能直接认为 Redis 一定会自动退回旧的 dump.rdb，需要根据损坏情况、截断加载配置和备份做恢复，避免把不完整的数据恢复当成正常启动。[原文§同时开启 RDB 和 AOF，重启时加载哪个？](https://xiaolincoding.com/interview/redis.html#%E5%90%8C%E6%97%B6%E5%BC%80%E5%90%AF-rdb-%E5%92%8C-aof-%E9%87%8D%E5%90%AF%E6%97%B6%E5%8A%A0%E8%BD%BD%E5%93%AA%E4%B8%AA)
