T2-63 的范围截断规则已独立核对 [RFC 9110 §14.1.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.1.2)。T3-75 的状态变化已独立核对 [RFC 9293 §3.10.7.4](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.10.7.4)：收到 ACK 后还要继续处理同一报文中的 FIN。

## 原文自身的技术条件与时效

以下不能归为“题库没有忠实转述原文”。修订时应遵循项目已有例外规则：注明原文表述，并添加“核对来源：”官方资料链接。

| 题号 | 核对结果与建议 |
| --- | --- |
| T5-57 | POSIX `send` 出错返回 `-1`，错误原因写入 `errno`；原文和题干把 EAGAIN/EWOULDBLOCK 写成直接返回值。应改为 `errno` 可能是哪两个错误码。 |
| T5-56 | “返回值小于请求长度”还包括 `-1`，不能一概按已成功发送部分字节处理；应限定成功返回且 `0 < n < length`，错误另按 `errno` 处理。 |
| T3-194 | 乱序会产生重复 ACK 并可能触发不必要的重传，不等于已经丢包；建议区分真正丢包与误判丢包，保留“丢包不一定意味着拥塞”的核心。 |
| T2-150 | “所有 DNS 服务器都有根服务器信息”过于宽泛，应限定需要执行从根开始的迭代解析的解析器，区分权威服务器和转发解析器。 |
| T2-289 | `least_time` 的可用范围有版本变化，按原文作答与现行产品规格须区分；不把按原文问法的正确标记视为硬错误。详见应用层报告的官方版本依据。 |

`send` 的返回值和错误处理应以 [POSIX send 定义](https://pubs.opengroup.org/onlinepubs/9799919799/functions/send.html)为依据；相关限定与原文差异见分章报告。本轮未在 Windows 上冒充运行 POSIX/Linux 实验。
