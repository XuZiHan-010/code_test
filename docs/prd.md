# PRD：面试题答题系统（基础版）

状态：草稿。需求部分已由 `specs/001-interview-quiz-system/spec.md` 取代，两者不一致时以 spec 为准；本文件保留实现决策、模块划分和测试决策，供规划阶段参考。标有【待确认】的决策是按推荐方案写的，尚未得到确认。

## Problem Statement

我手里有一套整理好的面试题库：15 个专题、151 个章节、2884 道题，每道题都有参考答案和原文出处。但它现在只是一堆 Markdown 文件，题卷和答案分开放，全部是简答题。

用它复习很不方便：

- 只能自己对着文件默答，再翻另一个文件找答案，没有任何反馈。
- 不知道自己哪一章掌握得好、哪一章差，做过多少也没有记录。
- 做错的题没有地方沉淀，下次复习还是从头翻。
- 全是简答题，每道都要组织大段文字，做起来慢，很多只需要辨认或列举的知识点也被迫写成长答案。
- 只有我自己能用，别人想用得先拿到文件。

## Solution

一个部署在 Railway 上的网页答题系统，多个用户各自注册登录后使用。

- 题库里的每一章都能在网页上做，2884 个知识点全部覆盖。
- 每个知识点按内容特点设计成单选题、多选题或简答题三者之一。
- 一章做完交卷后，看到本章正确率，以及每道题的正确答案和完整解答（参考答案加原文出处）。
- 系统记录每个用户每一章的完成情况。
- 用户能看到自己每一章的错题，以及每道题错过几次。
- 用户可以把任意题目加入自己的“错题本”，错题本本身是一个可以反复练习的题集。

## 术语

| 术语 | 含义 |
| --- | --- |
| 专栏 | 题库的四个来源：大模型面试题、Claude Code、Codex、图解 Agent |
| 专题 | 一份题卷，共 15 个，每个有唯一的题号前缀字母（如 RAG 是 `B`） |
| 章节 | 题库里的一个题组，对应一篇原文，共 151 个。编号为“前缀 + 题组号”，如 `B1` |
| 知识点 | 题库里原有的一对题干和参考答案，共 2884 个，以题号标识，如 `B1-1` |
| 题目 | 网页上呈现的题，由一个知识点转换而来，题型为单选、多选或简答，沿用该知识点的题号 |
| 解答 | 题目作答后展示的内容：知识点的参考答案全文和原文小节链接 |
| 作答 | 用户对一章（或错题本）的一次完整练习，从开始到交卷 |
| 错题 | 用户至少判错过一次的题目 |
| 错题本 | 用户自己手动挑选题目组成的题集，每个用户一个 |

## User Stories

### 账号

1. 作为访客，我想用用户名和密码注册账号，以便我的答题记录归到我名下。
2. 作为注册用户，我想登录和退出，以便在不同设备上继续我的进度。
3. 作为注册用户，我想保持登录状态一段时间，以便不用每次打开都重新登录。
4. 作为注册用户，我想确信别人看不到我的答题记录和错题本，以便放心使用。
5. 作为访客，我在未登录时访问答题页面会被带到登录页，登录后回到原来想去的页面，以便流程不中断。
6. 作为注册用户，我想在注册时得到明确的错误提示（用户名已占用、密码太短），以便知道怎么改。

### 浏览题库

7. 作为用户，我想在首页看到按专栏分组的 15 个专题，以便找到想练的方向。
8. 作为用户，我想看到每个专题下的章节列表和每章的题数，以便估计做一章要多久。
9. 作为用户，我想在章节列表上看到每一章的状态（未开始、进行中、已完成），以便知道自己做到哪了。
10. 作为用户，我想在章节列表上看到已完成章节的最近一次正确率和最高正确率，以便知道哪些章节要重做。
11. 作为用户，我想看到每个专题的整体进度（已完成章节数 / 总章节数），以便掌握全局。
12. 作为用户，我想看到每一章对应的原文标题和链接，以便先读原文再做题。

### 做题

13. 作为用户，我想开始做某一章，按题库原有顺序逐题作答，以便跟着原文的讲解顺序复习。
14. 作为用户，我想做单选题时从选项里选一个，以便快速检验是否认得出正确说法。
15. 作为用户，我想做多选题时选多个选项，并且题目明确标出这是多选题，以便知道要选全。
16. 作为用户，我想做简答题时在文本框里写答案，以便练习自己组织语言。
17. 作为用户，我想看到当前是第几题、本章共几题，以便知道进度。
18. 作为用户，我想在一章内自由前后跳题、修改已答的题，以便先做会的。
19. 作为用户，我想有一个本章题目概览，标出哪些已答、哪些未答，以便交卷前查漏。
20. 作为用户，我的每一次作答都自动保存，以便关掉页面或断网后不丢失。
21. 作为用户，我想中途离开后回来能从上次的位置继续，以便分几次做完一个长章节（最长的一章有 71 题）。
22. 作为用户，我在交卷前看不到正确答案，以便练习结果真实。
23. 作为用户，我想在还有未答题时交卷得到提醒并可以选择仍然交卷，以便不会误交。
24. 作为用户，我想放弃一次进行中的作答并重新开始，以便状态乱了时能重来。

### 看结果

25. 作为用户，我想交卷后立刻看到本章正确率（答对题数 / 本章总题数），以便知道掌握程度。
26. 作为用户，我想在结果页看到每道题我答了什么、正确答案是什么、判对还是判错，以便逐题核对。
27. 作为用户，我想在结果页看到每道题的完整解答（参考答案全文）和原文小节链接，以便把知识点补完整。
28. 作为用户，我想在选择题的结果里看到每个选项哪些对、哪些错，以便知道自己错在哪个选项。
29. 作为用户，我想在简答题的结果里看到判定结果和简短的评语（答到了什么、漏了什么），以便知道差距。
30. 作为用户，我想在结果页只筛出答错的题，以便集中看错题。
31. 作为用户，我想在简答题评分暂时不可用时仍然看到其余题目的结果，未评出的题标为“待评分”并稍后自动补评，以便不被卡住。
32. 作为用户，我想随时回看某一章最近一次作答的结果页，以便复盘。
33. 作为用户，我想重做一章，新的一次作答不覆盖历史记录，以便看到自己的进步。

### 每章错题

34. 作为用户，我想查看某一章里我做错过的所有题目，以便针对性复习。
35. 作为用户，我想看到每道错题错过几次，以便分清偶然失误和真正的薄弱点。
36. 作为用户，我想看到每道错题最近一次是对是错，以便知道现在是否已经掌握。
37. 作为用户，我想在错题列表里直接展开看题目、正确答案和解答，以便不用重做也能复习。
38. 作为用户，我想按错误次数排序错题，以便先看错得最多的。
39. 作为用户，我想有一个跨章节的错题总览（按专题、章节汇总错题数），以便找到最薄弱的章节。
40. 作为用户，我想未作答就交卷的题不被算作错题，以便错题记录只反映我真正答错的内容。

### 错题本

41. 作为用户，我想在结果页把任意一道题加入错题本，以便留下我认为值得再练的题。
42. 作为用户，我想在每章错题列表里把题目加入错题本，以便从错题里挑重点。
43. 作为用户，我想加入错题本的题不限于做错的题，以便把做对但没把握的题也放进去。
44. 作为用户，我想在任何显示题目的地方看出它是否已在错题本里，以便不重复操作。
45. 作为用户，我想从错题本里移除题目，以便掌握之后把它清出去。
46. 作为用户，我想查看错题本里的全部题目，并看到每道题来自哪个专题和章节、错过几次，以便整理。
47. 作为用户，我想把错题本当成一个题集来练习，流程和做一章一样（作答、交卷、看正确率和解答），以便反复巩固。
48. 作为用户，我想在错题本练习里答错的题同样累计错误次数，以便错误次数反映全部练习。
49. 作为用户，我想错题本为空时看到说明和引导，以便知道怎么往里加题。

### 题目内容（内容维护者视角）

50. 作为内容维护者，我想每个知识点都恰好对应一道题目，以便题库没有遗漏。
51. 作为内容维护者，我想题型按知识点内容决定，而不是按固定比例分配，以便每种题型用在合适的地方。
52. 作为内容维护者，我想选择题的选项和干扰项只取材于同一篇原文的内容，以便遵守题库“只按原文出题”的规则。
53. 作为内容维护者，我想有一个校验步骤在题目数据不合格时直接失败并指出题号，以便坏数据进不了线上。
54. 作为内容维护者，我想能单独重新生成某一章或某一道题而不影响其他题目，以便修正个别质量差的题。
55. 作为内容维护者，我想题号在转换前后保持不变，以便用户的答题记录和错题本不会因为内容更新而失效。

## Implementation Decisions

### 章节的定义

- “章”就是题库里的题组，一篇原文一章，共 151 章，挂在 15 个专题之下。不把专题当作一章，因为最大的专题有 485 题，无法一次做完。
- 章节规模：最少 7 题，中位数 15 题，最多 71 题，有 13 章超过 40 题。因此作答必须支持自动保存和中途续做。

### 题型设计

- 每个知识点转换成恰好一道题目，沿用原题号。
- 题型判断标准：
  - **单选题**：答案是一个明确的事实、判断或选择（“是不是”“哪一种”“用什么”）。
  - **多选题**：答案是一组并列的要点（“有哪几个步骤”“哪三个痛点”“包含哪些部分”）。
  - **简答题**：答案是机制、原因、取舍或对比，需要成段解释才能说清。
- 单选题固定 4 个选项、1 个正确；多选题 4 到 6 个选项、至少 2 个正确。
- 选择题可以改写题干以适配选项形式，但考查的知识点不变。
- 选项和干扰项只能取材于同一章的原文内容（该题和同章其他题的参考答案），不引入原文之外的说法。
- 无论题型，解答都是原参考答案全文加原文小节链接，原样展示。

### 题目数据怎么产生

- 题型转换是离线的内容生成步骤，不在网站运行时进行。用大模型按章批量生成，结果存成结构化数据随代码一起提交。
- 生成结果必须通过校验才能进入应用：
  - 2884 个题号全部覆盖，无缺失、无重复；
  - 题型合法，选项数量和正确项数量符合上面的约束；
  - 选项无重复、无空项；
  - 每道题保留原参考答案和至少一条原文引用。
- 生成按章进行，可以单独重跑某一章或某一题。
- 上线前按专题抽查生成质量。

### 题目内容与用户数据分离

- 题目内容是静态数据，随应用发布，启动时加载进内存，不存数据库。
- 数据库只存用户和用户产生的记录，通过题号和章节编号引用题目。
- 这样更新题目内容只需要重新发布，不需要数据迁移；前提是题号保持稳定。

### 判分

- 判分全部在服务端进行。交卷之前，正确答案、选项对错和解答都不下发到浏览器。
- 单选题：选中的选项与正确项一致即判对。
- 多选题：选中的集合与正确项集合完全一致才判对，多选、少选、错选都判错，不给部分分。
- 简答题（已确认）：交卷后调用大模型评分，使用 DeepSeek 的 API。输入题干、参考答案和用户答案，输出“对 / 错”和一两句评语。判对的标准是覆盖了参考答案的主要要点，不要求措辞一致。
- 简答题评分通过一个统一的评分接口接入，大模型只是其中一种实现，便于以后更换模型或改成其他评分方式。
- 评分服务失败或超时时，该题标为“待评分”，不计入本次正确率的分子，后台重试；重试成功后更新结果和正确率。
- 对每个用户的简答题评分请求做频率限制，防止滥用产生费用。
- 正确率 = 判对题数 / 该次作答的总题数。未答题计入分母，不算答对。

### 作答与完成情况

- 作答的范围有两种：某一章，或用户的错题本。
- 一次作答有三个状态：进行中、已交卷、已放弃。同一用户对同一范围同时只有一次进行中的作答。
- 每答一题立即保存；交卷前可以修改。
- 交卷后该次作答不可再修改。重做会创建新的一次作答，历史保留。
- 章节状态由作答记录推导：没有作答为“未开始”，有进行中的作答为“进行中”，有已交卷的作答为“已完成”。
- 错题本练习开始时，题目列表按当时错题本的内容固定下来，练习过程中增删错题本不影响这次作答。

### 错题与错误次数

- 错误次数按“用户 + 题号”累计：每次交卷时该题被判错就加一，章节作答和错题本练习都算。
- 未作答的题不累计错误次数，也不成为错题。
- 错题不会因为后来答对而消失，但会显示最近一次的对错。
- 每章错题、跨章错题总览都是在这份按题累计的记录上按章节、专题聚合。

### 错题本

- 每个用户一个错题本，内容完全由用户手动增删，系统不会自动往里加题。
- 任意题目都可以加入，不要求曾经做错。
- 同一道题只能加入一次，重复添加不报错也不产生重复项。
- 错题本和“每章错题”是两个独立的东西：前者是用户挑的题集，后者是系统统计的记录。

### 账号【待确认】

- 用户名加密码注册和登录，不做邮箱验证和找回密码。
- 密码只存哈希；登录状态用服务端会话加 Cookie 维持。
- 所有答题、错题、错题本接口都只能访问当前登录用户自己的数据。

### 技术栈【待确认】

- 一个全栈 Web 应用（前后端同一个服务），TypeScript，部署为一个 Railway 服务。
- 数据库用 Railway 提供的 PostgreSQL。
- 推荐框架为 Next.js，数据库访问用带迁移功能的 ORM。
- 密钥（数据库连接、会话密钥、大模型 API Key）只通过 Railway 环境变量提供。

### 模块

1. **题库解析器**：读入题卷和答案两份 Markdown，输出结构化的知识点（题号、专题、章节、小节、题干、参考答案、原文引用）。纯函数，无外部依赖。
2. **题目数据校验器**：对生成后的题目数据集检查上面列出的全部约束，报告不合格的题号。纯函数。
3. **题型转换流水线**：离线工具，按章调用大模型生成题目，调用校验器，写出数据文件。
4. **题库目录**：运行时的只读查询接口。按专栏、专题、章节取题目；提供“作答视图”（不含答案）和“结果视图”（含答案和解答）两种输出，保证未交卷时答案不会泄露。
5. **判分引擎**：给定题目和用户答案，返回判定。选择题部分是纯函数；简答题通过评分接口委托给外部实现。
6. **简答题评分器**：评分接口的大模型实现，包含提示词、结果解析、超时和重试。
7. **作答服务**：开始、续做、保存答案、交卷、放弃；计算正确率；推导章节状态。
8. **错题统计**：交卷时更新按题累计的记录；提供按章、按专题的错题查询。
9. **错题本服务**：增、删、查、是否已加入，以及为错题本练习固定题目列表。
10. **账号与会话**：注册、登录、退出、当前用户识别。
11. **页面**：首页与专题列表、章节列表、答题页、结果页、每章错题页、错题总览、错题本页、登录注册页。

### 数据模型（概念）

- 用户：用户名、密码哈希。
- 会话：所属用户、过期时间。
- 作答：所属用户、范围（章节编号或错题本）、状态、题目列表、开始时间、交卷时间、正确率。
- 作答明细：所属作答、题号、用户答案、判定（对、错、未答、待评分）、评语。
- 题目统计：用户、题号、错误次数、作答次数、最近一次判定。
- 错题本条目：用户、题号、加入时间。

## Testing Decisions

好的测试只验证模块对外的行为：给定输入，断言输出或可观察到的状态变化。不断言内部函数的调用方式、不依赖实现细节，这样重构内部实现时测试不需要跟着改。

仓库里目前没有任何测试，没有可参照的先例；本项目的测试约定从这次开始建立。

要写测试的模块：

- **题库解析器**：用真实题库文件做输入，断言解析出 15 个专题、151 章、2884 个知识点，题卷与答案题号一一对应；另用小的手写样例覆盖几种格式变体（有无 `###` 小标题、一题多条引用、题组下有无“原文”行）。
- **题目数据校验器**：对每条约束各构造一份不合格数据，断言校验失败并指出正确的题号；合格数据通过。
- **判分引擎**：单选对错；多选的全对、少选、多选、错选；未答；简答题通过假的评分实现验证判对、判错、评分失败三条路径。
- **作答服务**：开始与续做、保存后修改、交卷后不可改、未答题计入分母、正确率计算、同一范围只有一个进行中作答、重做保留历史、章节状态推导。
- **错题统计**：判错累计次数、未答不累计、后来答对不清除但更新最近判定、错题本练习同样累计、按章和按专题聚合。
- **错题本服务**：添加、重复添加不产生重复项、移除、不同用户互不可见、练习开始后题目列表固定。
- **账号与会话**：注册校验、用户名重复、登录成功与失败、未登录访问受保护接口被拒、用户之间数据隔离。

作答服务、错题统计、错题本服务、账号这四块连真实数据库做测试，不用模拟的数据库。

不写自动化测试的部分：

- 题型转换流水线的生成质量靠校验器加人工抽查保证，不对大模型输出写断言。
- 简答题评分器对真实大模型的调用不进自动化测试；只测它对各种返回（正常、格式错误、超时）的处理。
- 页面的视觉样式。

## Out of Scope

- 后续的拓展功能（待补充后另行规划）。
- 自动把错题加入错题本、按错误次数自动推荐复习、间隔重复等错题策略。
- 多个错题本或自定义命名的题集。
- 邮箱验证、找回密码、第三方登录。
- 管理后台和在线编辑题目。
- 排行榜、用户之间的任何互动。
- 限时考试、随机抽题组卷。
- 多选题和简答题的部分得分。
- 用户对评分结果提出异议或手动改判。
- 题库内容本身的增补和修订。
- 移动端原生应用（网页需在手机浏览器上可用，但不单独做 App）。

## Further Notes

- **内容生成是最大的一块工作量。** 2884 个知识点都要判断题型，其中的选择题还要写选项和干扰项。建议先拿一个专题（如题量最小的 AI 编程，65 题）跑通生成、校验、抽查的全流程，确认质量后再铺开到全部专题。
- **简答题评分会产生持续费用**，并且需要在 Railway 上配置 DeepSeek 的 API Key。评分方式已确认为大模型自动评分。
- **用户专属题库是后续方向**：用户在网页上传 PDF 或提供链接，由大模型生成只属于自己的题库。届时用户填写自己的 API Key，生成费用由用户承担。它不在 1.0 范围内（已确认），1.0 不为它预留任何结构：以后加入时，给用户记录补一个“所属题库”字段并默认指向基础题库即可，现有题号不需要改动。
- **题库内容可以公开发布**（已确认）。题库是对 xiaolinnote.com 原文的摘编，来源内容是开源的。每道题的解答必须保留原文小节链接，页面上注明内容来源。
- 题库 README 说明答案是对原文的转述，原文里的经验数字、产品命令和阈值以写作时为准。结果页展示解答时应附带这一说明，不把它们呈现为现行官方规格。
- 题号是用户记录与题目内容之间唯一的关联，任何内容更新都必须保持题号不变。
