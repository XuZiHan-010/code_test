## 确认需修：原文 workqueue 的全称表述过宽

涉及 V6-43、V6-44、V6-45、V6-47（同一问题，勿按4个独立技术错误统计）。

- V6-43：正确A“把任务交给工作线程，在进程上下文执行，允许使用可以睡眠的操作”；B“在中断返回路径中直接执行，不允许睡眠”标错。
- V6-44：D“工作队列的任务”标错；解答说“只有工作队列在进程上下文执行，允许使用可以睡眠的操作”。
- V6-45：正确D“工作队列”；解答没有限定工作队列类别。
- V6-47：简答直接说“工作队列把任务交给工作线程，在进程上下文执行，允许使用可以睡眠的操作”。

原文对应小节确实使用上述简化，但现代 Linux 的 workqueue 不全是线程上下文：内核官方文档明确区分 threaded workqueue 和 BH workqueue，WQ_BH 工作项运行于 softirq 上下文，不能睡眠。因此不能把“全部 workqueue 都允许睡眠”作为无条件规则。V6-44 的错误项尤其会把不能睡眠的 BH 工作项一并排除。

影响：基础对比的意图正确，默认常见线程工作队列下现有答案也正确，但作为不限类别的技术结论会误教上下文约束。

最小修正：这4题题干/选项/解答统一把这里的“工作队列”限定为“常见的线程工作队列（threaded workqueue）”。不增加 WQ_BH 考题；解答按项目规则括注原文将 workqueue 泛称为工作线程执行，补“核对来源”链接，说明本题收窄到线程工作队列。无需改题号、题型或正确项。

依据：[原文对应小节](https://xiaolincoding.com/interview/os.html#硬中断、软中断和工作队列有什么区别)；[Linux 官方 Workqueue 文档 The Design / WQ_BH](https://docs.kernel.org/core-api/workqueue.html#flags)，明确存在两种执行上下文并说明 BH 工作项不能睡眠。

## 仅边界建议，不计作明确错题

### B1：V7-66、V7-71 的 read 返回0应限定流式Socket、读取长度大于0

当前 V7-66 题干“读数据时 read 返回0，通常表示什么”，正确B“通常表示对端已有序关闭发送方向”；V7-71 简答也使用相同表述。该节上下文是网络接收，预期指 TCP，故预期答案清楚；但独立呈现后没有写明流式 Socket，普通文件的EOF及零长度读取都能返回0。相邻 V7-77 已写“非阻塞的流式 Socket”，是更好的范围限定。

最小方向：V7-66 写“对流式 Socket 调用 read（请求读取字节数大于0）返回0”；V7-71 对应一句加流式Socket范围。无需引入其他fd考点。

依据：[原文ET小节](https://xiaolincoding.com/interview/os.html#epoll-的-边缘触发和水平触发有什么区别)；[Linux read(2)](https://man7.org/linux/man-pages/man2/read.2.html) DESCRIPTION / RETURN VALUE。

### B2：V7-73 的 EAGAIN 场景最好写出非阻塞条件

当前题干“多个线程操作同一个Socket，其他线程先把数据读走了，当前线程再读会怎样”，正确A“可能得到EAGAIN”。答案中的“可能”允许理解为存在非阻塞配置，故没有明确错标；但若Socket是阻塞的，通常重新等待，而非得到EAGAIN。原文也先举竞态例子、随后才建议非阻塞，拆题时可把该前提补在本题。

最小方向：题干改“多个线程操作同一个非阻塞Socket……”。

依据：[原文对应小节](https://xiaolincoding.com/interview/os.html#epoll-返回可读后-read-就一定能读到数据吗)；[Linux read(2) ERRORS](https://man7.org/linux/man-pages/man2/read.2.html)，Socket的EAGAIN/EWOULDBLOCK条件包含O_NONBLOCK且该读取本会阻塞。

### B3：V7-67 的 ET 写入处理可以更完整，但不能直接判错

当前正确B“要处理部分写入，保存尚未发送的数据，等可写时继续发送”。建议解释中补“继续尝试发送到完成或EAGAIN，再等待后续可写通知”，避免被理解成每写一次就无条件重新等事件。

这只是补强：Linux epoll(7) 还允许对流式fd通过短读/短写判断I/O空间耗尽，因此不能仅凭“部分写入后等待”就认定本题一定会卡死，也不能把此处列成已确认技术错误。

依据：[原文ET小节](https://xiaolincoding.com/interview/os.html#epoll-的-边缘触发和水平触发有什么区别)；[Linux epoll(7)](https://man7.org/linux/man-pages/man7/epoll.7.html) 的ET使用建议及 Questions and answers 中流式fd短读/短写说明。

- V7-30 的D“哪些连接已经被对端完整关闭”标错：关闭确实能导致就绪事件，但本题问“原文举的例子”，原文该句只举可读/可写，不能据此判成多正确项。若希望更独立，可把D改成明确非就绪事件；不作为必须修正。

- V5 的fd/inode、硬软链接、unlink引用、Page Cache、同步持久化、mmap六节均有范围词或合理上下文，没有发现需要纠正的技术结论；尤其write成功不等于落盘、fflush不代替fsync、目录同步和MAP_PRIVATE不写回等条件均已覆盖。
