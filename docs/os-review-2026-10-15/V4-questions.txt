### V4-1 (single) 介绍一下操作系统内存管理
按原文，操作系统设计虚拟内存后，进程的地址空间是怎样的？
A [错误] 所有进程共用同一个虚拟地址空间，靠页表区分各进程的数据
B [正确] 每个进程都有自己独立的虚拟地址空间，程序通常不直接与物理内存打交道
C [错误] 每个进程直接使用物理地址访问数据，虚拟地址只在启用 Swap 时才出现
D [错误] 进程的虚拟地址空间大小必须与物理内存大小完全相同
解答：操作系统设计了虚拟内存，每个进程都有自己的独立虚拟地址空间，我们所写的程序通常不会直接与物理内存打交道。其余说法都与此相反：虚拟地址空间是每个进程独立的，不是共用的；程序通常使用虚拟地址而不是物理地址；虚拟地址空间可以比物理内存更大，并不要求大小相同。[原文§介绍一下操作系统内存管理]

### V4-2 (short) 介绍一下操作系统内存管理
按原文，虚拟内存为什么能让进程使用比物理内存更大的虚拟地址空间？这是否意味着实际可用内存没有限制？
解答：进程可以使用比物理内存更大的虚拟地址空间，不必把所有页面同时放进物理内存。原因是程序运行符合局部性原理，可以只保留当前常用的页面：文件页按需重新读取，不常用的匿名页在启用 Swap 时可以换出。不过，这不代表实际可用内存没有限制，频繁换入换出还会明显拖慢程序。[原文§介绍一下操作系统内存管理]

### V4-3 (single) 介绍一下操作系统内存管理
按原文，虚拟内存为什么能解决多进程之间的地址冲突问题？
A [错误] 所有进程共用一张页表，由操作系统为每个进程分配互不重叠的虚拟地址范围
B [错误] 页表项里的读写权限比特禁止了不同进程使用相同的虚拟地址
C [错误] 进程不必把所有页面同时放进物理内存，所以不同进程的地址不会重叠
D [正确] 每个进程有自己的页表，进程之间的虚拟地址空间相互独立，也无法访问其他进程的页表
解答：由于每个进程都有自己的页表，所以每个进程的虚拟内存空间相互独立；进程也没有办法访问其他进程的页表，这些页表是私有的，这就解决了多进程之间地址冲突的问题。共用一张页表、依靠读写权限比特或不必全部放进物理内存，都不是原文给出的原因。[原文§介绍一下操作系统内存管理]

### V4-4 (multiple) 介绍一下操作系统内存管理
按原文，下列哪些属于虚拟内存带来的好处？
A [正确] 进程可以使用比物理内存更大的虚拟地址空间，不必把所有页面同时放进物理内存
B [正确] 每个进程有各自私有的页表，虚拟内存空间相互独立
C [错误] 实际可用内存不再有限制，频繁换入换出也不会拖慢程序
D [正确] 页表项中的读写权限、是否存在等标记比特，让内存访问更安全
E [错误] 所有进程共享同一张页表，因此可以互相访问对方的页面
解答：虚拟内存带来三点好处：进程可以使用比物理内存更大的虚拟地址空间；每个进程有自己的私有页表，地址空间相互独立；页表项中的读写权限、是否存在等标记比特提供了更好的安全性。实际可用内存仍然有限制，频繁换入换出还会明显拖慢程序；进程也无法访问其他进程的页表，页表是私有的，不是共享的。[原文§介绍一下操作系统内存管理]

### V4-8 (single) 介绍一下操作系统内存管理
按原文，当进程访问页面时，CPU 在什么情况下会产生缺页异常？
A [错误] 每一次访问内存都会产生缺页异常，再由内核判断是否放行
B [错误] 只要访问的映射没有缓存在 TLB 中就会产生缺页异常
C [正确] 访问的页面尚未驻留，或者访问违反了页表记录的权限
D [错误] 只有进程第一次启动时才会产生缺页异常
解答：当进程访问的页面尚未驻留，或者访问违反页表记录的权限时，CPU 会产生缺页异常。并不是每次访问内存都会触发；至于 TLB 未命中，原文在 TLB 一节明确说它不等于缺页。[原文§介绍一下操作系统内存管理]

### V4-9 (single) 介绍一下操作系统内存管理
按原文，内核处理缺页异常时，会怎样区别对待不同的访问？
A [错误] 一律向进程发送 SIGSEGV 信号，不再判断访问是否合法，由进程自己决定是否继续运行下去
B [错误] 一律从磁盘把页面读入内存后重试，不管访问是否合法，也不管页面是否真的需要读盘
C [错误] 忽略这次异常，不分配页面也不检查权限，直接重新执行触发异常的指令
D [正确] 先判断访问是否合法：合法的处理后重试；非法地址或真正的权限错误可能收到 SIGSEGV
解答：内核会判断这次访问是否合法：合法的按需分配、换入或写时复制可以处理后重试；非法地址或真正的权限错误，则可能向进程发送 SIGSEGV。所以并非一律终止，也并非一律读磁盘，更不能不处理就重试。[原文§介绍一下操作系统内存管理]

B [正确] 当前操作不满足访问权限时，会触发缺页异常
C [正确] 内核会判断能否通过分配页面、加载文件或写时复制等方式解决缺页

### V4-17 (single) 讲一下页表？
按原文，基本分页为什么避免了分段连续分配带来的外部碎片问题？
A [错误] 页的大小可以随程序需要变化，因此不会留下无法使用的空隙和浪费
B [正确] 连续的虚拟页可映射到不连续的物理页框，不需要一整块连续物理内存
C [错误] 每个页都被程序完全用满，因此页内不会出现内存浪费
D [错误] 内核申请大块连续物理内存时完全不受物理内存碎片的影响
解答：基本分页按固定大小的页框分配，连续的虚拟页可以映射到不连续的物理页框，不需要找到一整块连续物理内存，因此避免了分段连续分配带来的外部碎片问题。页是固定大小的；页内浪费属于内部碎片；原文还提醒内核申请大块连续物理内存时仍可能受物理内存碎片影响。[原文§讲一下页表？]

### V4-18 (single) 讲一下页表？
按原文，内存分页机制为什么会出现内部碎片？
A [错误] 连续的虚拟页必须映射到一整块连续的物理页框，造成空隙
B [错误] 每个段的长度可变，段与段之间会留下无法利用的空隙
C [错误] 页表本身存放在内存里，会额外占用一部分物理内存
D [正确] 最小分配单位是一页，不足一页的程序也要分配一个页，页内会浪费
解答：内存分页机制分配内存的最小单位是一页，即使程序不足一页大小，也最少只能分配一个页，所以页内会出现内存浪费，这就是内部内存碎片。连续虚拟页不要求映射到连续物理页框；段长可变是分段的特点；页表存放在内存里与内部碎片无关。[原文§讲一下页表？]

解答：应用程序通过 malloc 申请的是可用的虚拟地址范围，物理内存通常在访问时按需提供；访问尚未建立物理映射的合法页面时，CPU 产生缺页异常，内核尝试分配页面。如果没有空闲物理内存，内核开始回收内存，方式主要有两种：后台内存回收（kswapd）在空闲内存低于一定水位时唤醒内核线程回收，不由申请线程同步完成；直接内存回收在后台回收跟不上时开始，是同步的，会阻塞进程。如果直接回收后仍无法满足申请，就触发 OOM 机制，OOM Killer 根据内存占用、oom_score_adj 等因素选择进程终止，不一定杀死占用内存最多的进程。可回收的内存主要有两类：文件页（干净页直接释放，脏页先写回磁盘再释放）和匿名页（通过 Swap 换出到磁盘再释放）。回收时参考页面的访问活跃程度，传统实现采用近似 LRU 思路，用 active 和 inactive 链表来理解；Swap 没有启用或空间不足时，匿名页难以回收，内存压力更难缓解。[原文§操作系统内存不足的时候会发生什么？]

### V4-148 (short) 页面置换有哪些算法？
按原文，时钟页面置换算法是怎样选择要淘汰的页面的？
解答：把候选页面组织成一个类似钟面的环，一个表针指向下一个要检查的页面，通过访问位给近期访问过的页面一次机会。发生缺页中断时，先检查表针指向的页面：如果它的访问位是 0，就淘汰该页面，把新页面插入这个位置，并把表针前移一个位置；如果访问位是 1，就清除访问位，并把表针前移一个位置，重复这个过程直到找到访问位为 0 的页面为止。[原文§页面置换有哪些算法？]
