## 确认需修

### 1. V4-35：单题缺少计算前提

- 当前题干：“假设每个页表项占4字节，上面的单级页表要占用多少内存？”D“4MB”标为正确。
- 问题：本题没有32位虚拟地址、4KB页大小，“上面的”依赖V4-34。随机练习或错题单独出现时无法计算页表项数量。答案4MB本身在原文条件下正确。
- 影响：独立作答所需信息缺失。
- 最小修正：把“32位虚拟地址空间、页大小4KB”直接加入实际选择题题干及题卷。
- 依据：[原文多级页表](https://xiaolincoding.com/interview/os.html#为什么要用多级页表)，原文明确给出完整参数；README要求拆成可单独提出的短问题。

### 2. V4-143、V4-154：数值例题缺少页面请求序列

- V4-143当前：仅给“同一请求页面序列、3个物理页”，三个空答案依次7、10、9。
- V4-154当前：比较三种算法及“原文例子中的表现”；答案给OPT缺页7/置换4、FIFO缺页10/置换7、LRU缺页9/置换6。
- 问题：两题都没有展示页面请求序列；V4-154连3个初始空闲页也未写。原文数值来自图中的特定序列，不是算法的固定属性。现题只能背原文数字，不能就题面核验或推演。
- 影响：情景条件不完整；无法从题面判断数值答案。
- 最小修正：从原文置换图抄入完整请求序列、3个初始空闲物理页；V4-154也可以删掉数值表现部分，仅比较算法思路。无需新增考点。
- 依据：[原文页面置换](https://xiaolincoding.com/interview/os.html#页面置换有哪些算法)，原文明确“假设一开始有3个空闲物理页”，并把请求序列放在配图。
- 验证限制：本轮已逐字核对原文正文7/10/9及4/7/6与答案一致，但尚未对配图序列逐步重新模拟，因此不把这些数字报告为算错。

### 3. V3-8、V3-9、V3-21：把互斥锁竞争失败一概描述为立即睡眠/线程切换

- V3-8解析：“睡眠并发生线程切换是互斥锁应对加锁失败的方式”；本题D自旋忙等待正确，标记无需改。
- V3-9正确A：“互斥锁用‘线程切换’来应对，自旋锁用‘忙等待’来应对”；解析称“实现完全不同”。
- V3-21简答解析同样把两者做完全对立描述。
- 问题：原文这里采用阻塞式互斥锁的简化比较，却写成互斥锁的一般实现规律。glibc自适应互斥锁会先有限自旋，达到上限才进入内核阻塞，也可能自旋期间就成功获取。
- 影响：解析教给用户错误的实现排他关系；不构成V3-9其他选项也正确，但A应加边界。
- 最小修正：写成“以阻塞等待的互斥锁为例，竞争持续时可阻塞并让出CPU；纯自旋锁忙等待。具体互斥锁实现也可能先自旋再阻塞”；注明原文采用简化比较，并附核对来源。V3-8实际题干/答案不需变。
- 原文依据：[自旋锁小节](https://xiaolincoding.com/interview/os.html#自旋锁是什么-应用在哪些场景)。
- 官方核对依据：[glibc POSIX Thread Tunables](https://sourceware.org/glibc/manual/latest/html_node/POSIX-Thread-Tunables.html)，mutex_spin_count说明自适应互斥锁先自旋、再进入内核阻塞。外源仅纠正原文已有比较，不新增题目。

### 4. V4-123、V4-135：直接回收失败必然触发OOM的说法丢失例外

- V4-123正确D：“直接内存回收后，空闲物理内存仍然无法满足此次申请”；解析“那么内核就会触发OOM机制”。
- V4-135简答同样写“如果直接回收后仍无法满足申请，就触发OOM机制”。
- 问题：原文同节紧接着已有“有些分配也可能直接失败，具体取决于分配方式和系统配置”，V4-124参考答案也保留该限定，但这两题单独出现时限定丢失。官方API明确某些允许直接回收的分配标志在失败时避免触发OOM killer。
- 影响：把常见分配路径写成无条件结论。
- 最小修正：改“回收后仍不能满足申请时，可能进入OOM处理；部分分配可以直接失败，取决于分配方式和配置”。V4-123可把题干明确为“常见可触发OOM的分配路径”，或给D加“可能”。
- 依据：[原文内存不足](https://xiaolincoding.com/interview/os.html#操作系统内存不足的时候会发生什么)；[Linux Memory Management APIs / Reclaim modifiers](https://www.kernel.org/doc/html/latest/core-api/mm-api.html#reclaim-modifiers)，__GFP_NORETRY可做轻量直接回收并避免OOM killer，__GFP_RETRY_MAYFAIL也可失败而不直接调用OOM killer。
