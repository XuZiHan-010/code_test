## 确认需修

### V2-107：单选存在第二个正确选项（高）

- 当前：A“互斥锁等同步对象的状态”标正确；B“其他线程的运行栈内容”标错误。问的是 fork 后父进程地址空间被继承，其中包含什么状态。
- 问题：其他线程不会作为可调度线程出现在子进程，不等于它们的用户栈内存消失。一般 fork 复制整个虚拟地址空间，包括其他线程栈所在映射的内容；Linux 通过写时复制实现。B 也成立。原文只讲线程消失和锁状态继承，没有声称其他线程栈内容不被继承。
- 影响：理解正确的用户可能选择 B 而被判错。
- 最小修正：保留 A，将 B 改成“其他线程继续执行的调度实体”，或其他确定不继承的执行实体描述；解析明确区分线程执行实体与栈内存内容。不要把 B 直接解释为“其他线程不存在所以栈内容不存在”。
- 依据：[原文 fork 小节](https://xiaolincoding.com/interview/os.html#多线程进程调用-fork-有什么需要注意的)；[Linux fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html) DESCRIPTION 明确整个虚拟地址空间复制，NOTES 说明写时复制。特殊 MADV_DONTFORK/WIPEONFORK 不改变该题无额外条件时 B 可成立的事实。

### V2-240：多级反馈队列的降级条件写反（高）

- 当前简答参考答案：“新进程进第一级队列，用不完时间片就逐级下移”。
- 问题：应为用完该级时间片仍未完成的任务降级。“用不完时间片”包含提前阻塞/让出，与同题组 V2-231、233、241 及原文方向相反。
- 影响：会把反馈队列对 I/O 交互任务与持续计算任务的区别教反，并影响简答评分。
- 最小修正：“用完该级时间片仍未完成的任务逐级下移”。
- 依据：[原文进程调度算法](https://xiaolincoding.com/interview/os.html#进程调度算法有哪些)明确“持续用完时间片”逐渐降级，以及规定时间片内“没运行完成”才转入下一级。

### V2-136：沿用原文把 FIFO 错称为设备文件（中）

- 当前 A 标正确：“需要在文件系统创建类型为 p 的设备文件，无关进程通过它通信”；参考答案重复“设备文件”。
- 问题：p 是 FIFO/命名管道特殊文件类型，不是字符或块设备文件。原文本身用了错误类别名。另题干“匿名管道只能在亲缘关系进程间通信”也比 V2-134、151 的“通常/持有同一管道端点”更绝对。
- 影响：教错 Unix 文件类型，并与本题组已保留的匿名管道本质要求产生冲突。
- 最小修正：A 与解析改“在文件系统创建 FIFO（命名管道）特殊文件，无关进程可通过路径名打开”；题干改“命名管道怎样方便没有亲缘关系的进程通信”。答案注明原文误称设备文件，并附核对来源。
- 依据：[原文进程间通信](https://xiaolincoding.com/interview/os.html#进程间通讯有哪些方式)；[Linux fifo(7)](https://man7.org/linux/man-pages/man7/fifo.7.html)明确称 FIFO special file/named pipe，说明 ls -l 类型为 p。V2-131 A 错误项也有“设备文件”用语，建议同步改准确，避免靠另一处错误构造干扰项；不将其另计错误题。

## 仅边界建议（不计确认错误）

1. **V2-199、200 的发送通知与持锁边界**：当前 D/简答为“在同一把锁保护下修改队列，并发送通知”。作为该例常见正确写法成立，但可能被读成 signal 必须在持锁期间调用。POSIX 允许通知时不持有 wait 使用的互斥锁；共享队列/谓词必须正确同步。建议解析加“本例可在持锁时通知；修改谓词与通知所需的同步应区分”。[POSIX pthread_cond_broadcast/signal](https://man7.org/linux/man-pages/man3/pthread_cond_broadcast.3p.html) DESCRIPTION 明确允许拥有或不拥有关联互斥锁时调用通知。
2. **V2-38 干扰项 C 协程**：线程和协程都可以并发并共享地址空间。当前题干明确“按原文……新实体”，解析明确是该节引出的线程，所以未判单选多解；为独立练习清晰度，可改“原文为解决多进程开销和共享数据问题引出的操作系统执行实体”。
3. **V2-181 C 读写锁读者准入**：当前“写锁没有被持有时多个线程能够并发持有读锁”作为能力描述成立；不要扩展成“只要当前无写持有者，新读者必定准入”，排队写者及实现策略可能影响后续新读者。
4. **V1-7、11 的用户态无法直接访问硬件**：与原文教学模型一致，通常有意指未经授权访问。建议避免把它扩展为所有硬件访问均不可能的架构定理（授权设备映射等存在）；本轮不据此改变明确按原文的答案集合。
