## 确认问题

1. **S1-82：把充分条件写成必要条件（中）。** 题干问“什么情况下才”，答案写“只有字段定义为 NOT NULL”。真正条件是当前统计的结果集中该字段没有 NULL；允许 NULL 的字段也可能每行都有值，甚至空结果集也会相等。该过度简化来自原文，题库又增加了“只有”。建议改问“哪种字段约束能保证对任意数据二者都相同”，或按结果集给出完整答案。核对来源：[MySQL COUNT 文档](https://dev.mysql.com/doc/refman/8.0/en/aggregate-functions.html)。SQLite 内存反例验证（用于演示相同的 SQL 语义，不代表跑过 MySQL）：可空列仅有 1、2 时两种 COUNT 都为 2；加入 NULL 后分别为 2、3。
2. **S1-66：解析把 IN 的结果简化成只有 TRUE/FALSE（中）。** 正确选项本身没有错，错在答案的“否则返回 FALSE”，遗漏未匹配且集合含 NULL 的 UNKNOWN，以及左侧 NULL 情况。该说法照搬原文前段，但与原文后段、现有 S1-71/S1-72 矛盾。建议直接利用同一小节后面的 NULL 说明补充条件。核对来源：[MySQL IN 文档](https://dev.mysql.com/doc/refman/8.0/en/comparison-operators.html)。
3. **S1-11、S1-16：缺少原表示例（中）。** 前者让学生指出哪两列不满足原子性，却没有字段及其内容；后者依赖原图的班主任姓名字段和学生主键。网页 QuestionCard 只显示本题题干、选项，不显示原图或章节背景。目前只能记忆原图，无法根据题内材料判断。建议补表格/字段与依赖关系，或改成完整、独立可答的范式题。
4. **S1-14：示例与解答不完整（中）。** 题干只提供联合主键，没有给出各字段的依赖关系；答案只说拆成两个表，没有列出订单表与订单明细表的键和字段分配。原文通过图说明调整结果。建议补齐示例表，并明确两张表如何分配字段。
5. **S1-106：依赖“同一个问题”（中）。** 单题题干没有说明要查“不存在 01、存在 02 课程”的学生。选项里可以猜出方向，但题目依赖上一题背景。错题本、独立练习不能保证出现上一题。建议在题干重述查询目标。

## 原文技术措辞待修正

6. **S1-43：“唯一作用场景”过于绝对（低）。** 原文和题库都称整数显示宽度只在 ZEROFILL 生效。MySQL 官方文档还说明客户端应用可以从结果元数据获取显示宽度，并自行以空格填充显示；是否使用取决于应用。建议改成询问 ZEROFILL 的具体补零行为，去掉“唯一”。这是沿用原文的绝对化说法，不是转述偏离。核对来源：[MySQL Numeric Type Attributes](https://dev.mysql.com/doc/refman/8.0/en/numeric-type-attributes.html)。
