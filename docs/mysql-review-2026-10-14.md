# MySQL 数据库题库审查（2026-10-14）

## 结论

已对照[小林coding MySQL 原文](https://xiaolincoding.com/interview/mysql.html)，逐题核对数据库栏目当前全部 8 章、669 题的题干、实际选项、正确标记和参考答案。存在会影响判分的出题问题，以及把原文示例拆题后丢失条件的问题。另有一些题忠实转述原文，但原文本身的技术条件不完整；这两类问题应分别处理。

本次只新增审查报告与证据文件，没有改题库、业务代码或章节的 `draft` 状态，没有执行 Git 提交或发布。

## 忠实转述，但原文本身需要限定或核对

这些不应归为“题库不符合原文”，也不宜直接把按原文回答的考生判错。按项目规则修订时，应说明原文如何表述，并附“核对来源：”官方资料链接。

| --- | --- |
| S3-95 | 子节点数量约束没有限定为内部节点；叶节点没有子节点。 |
| S6-15、S6-16 | 把 DELETE undo 固化成保存整行并重新插入，混淆逻辑撤销比喻与实际 delete-mark、undo、purge 实现。 |
| S6-5 | 提交时写入事务 binlog 缓存的流程应限定事务表，不能泛称所有 MySQL 存储引擎。 |
| S8-39 | 跨 database/schema 不必然跨实例；同一实例中的多个 InnoDB schema 可以在同一本地事务内修改。应限定跨实例/独立事务资源。 |
| S1-43 | 整数显示宽度的“唯一作用场景”说法过绝对；官方还说明客户端可利用返回的显示宽度元数据。 |

| S3-7 | 默认 InnoDB 的精确历史边界为 5.5.5，原文的 5.5 之后是概括说法。 |

官方证据及修订边界详见对应章节报告；本轮没有启动真实 MySQL 实例复现实验。

## 其他低优先级改进

- S3-26：把“匹配联合索引”限定为常规最左前缀定位，避免与原文另说的覆盖扫描、跳跃扫描例外混淆。
- S3-58：问索引“仍可能有效”，不宜把某个通常低收益的场景写成确定错误；应问原文列举的高价值场景，或把干扰项改成“一定有收益”。
- S3-133/134/135/140/141：补所指的联合索引和查询，删除对“上述查询”的依赖。
- S4-39/40：本题已有核心现象，可以判断机制，但仍建议去掉“上例中”。
- S4-59：写成 MVCC 关注的两个隐藏列，避免暗示总共只有两列。
- S4-61：可见结果正确，解释应保留自身未提交修改的例外。
- S4-20：对串行化读锁的概括补显式多语句事务条件。
- S6-40/41/49：独立题干补 redo/binlog 持久化配置前提。
- S8-15：题干改成应对复制延迟的读取策略；接受最终一致性本身不保证避免旧值。
