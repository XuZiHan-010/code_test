# 计算机网络题库修订计划

> 执行方式：使用 subagent-driven-development 组织内容修订、独立审查和验收；用户已要求直接修复。仅内容与文档变更，不改业务实现，不执行 Git 提交或发布。

**Goal:** 修复网络审查报告中的确认问题和明确的条件、引用、措辞建议，保留全部 656 个题号与题型数量。

**Architecture:** 三个分章任务分别输出独占的 JSON 修订提案，再由整合任务串行应用到同一组三个题库文件，避免并发覆盖。采用原文与官方核对规则；未确认项只在已有原文允许的范围澄清条件。

**Tech Stack:** UTF-8 Markdown、题型 JSON、现有 TypeScript 内容校验和 Vitest。

## Global Constraints

- 遵守根 AGENTS.md、CLAUDE.md 和题库 README 的来源、稳定题号与 draft 规则。
- 不新增、删除、重排题号，不改题型数量，不将章节设为 approved。
- 填空的 stem、标记、空数、顺序在 Markdown 与 JSON 同步；其他修订题也同步原题问法与答案适用条件。
- 原文技术勘误的参考答案需括注原文说法，并追加标签以“核对来源：”开头的官方链接。
- 保留所有已有其他专题和业务改动。不新增照抄题目文字的断言测试；用现有内容校验、单元测试以及逐项内容复核验证。
- 当前网络题库尚未跟踪且工作区有大量用户改动，直接修复用户指定工作区；修订前另存基线快照，验收比较本轮前后差异。
