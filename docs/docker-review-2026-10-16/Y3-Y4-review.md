### M1：tmpfs 被当作数据持久化方式，分类与本节自己描述的生命周期矛盾

**主体题及位置：**Y3-1（Q/A182、T2957）、Y3-2（Q/A183、T2964）、Y3-12（Q/A193、T3219）、Y3-13（Q/A194）。**关联解析：**Y3-5（A186，主体 Volume 命令识别及 C 正确标记无误）、Y3-28（A215）。Y3-1 的填空配置 3 空无序本身正确，问题是类别名称。

**现有文本：**Y3-1 题干称“三种容器数据持久化方式”；答案列 `Volume、Bind Mount、tmpfs`。Y3-2、Y3-5、Y3-12 继续以“持久化方式”作为总类，Y3-13 答案称“想持久化数据必须用外部存储，Docker 提供三种方式”，Y3-28 解析又称“tmpfs 是……数据持久化方式”。

**原文证据：**S350—373，开头将三者总称为持久化方式，但 tmpfs 项明确说容器停止数据就没了。题目忠实复制了原文错误，不能因“按原文”而豁免勘误规则。[原文对应小节](https://xiaolincoding.com/interview/docker.html#docker-容器数据持久化有哪些方式)

**官方核对：**tmpfs 是临时挂载，停止容器后挂载被移除，文件不保留；它用于不希望持久保存的数据。这与卷和绑定挂载的持久保存用途不同。[Docker tmpfs mounts](https://docs.docker.com/engine/storage/tmpfs/)

**影响与最小建议：**会让学习者将“内存临时存储”记成“持久化”，且与 Y3-8/9 冲突。保留三个术语和原题数，把总类改为“原文介绍的三种容器数据挂载/存储方式”；Y3-13 答案明确 Volume、Bind Mount 可用于持久化，tmpfs 是非持久临时存储，括注“原文将三者统称为持久化方式”，加“核对来源：”链接。关联题的总称及 Y3-28 解析同步改，不必改变现有正确选项集合。

### M2：Docker overlay 驱动与 Kubernetes 的 overlay 网络技术混为一谈

**题号及位置：**Y3-24（Q/A208；T3499 的 B 项 `Docker Swarm 或 Kubernetes 里的跨宿主机通信`，correct=true 在 T3500）；Y3-27（Q/A211 综合答案中的 overlay 部分）。

**现有文本：**“overlay 是跨宿主机的网络，通常在 Docker Swarm 或 Kubernetes 里使用。”

**原文证据：**S378—391 的主题是 Docker 网络模式，overlay 项直接把 Docker Swarm 与 Kubernetes 并列。[原文网络模式小节](https://xiaolincoding.com/interview/docker.html#docker-的网络模式有哪些)

**官方核对：**Docker 的 overlay 驱动要求宿主机加入 Swarm，即使连接独立容器也是如此；Kubernetes 网络由兼容的 CNI 插件实现。Kubernetes 中可能使用 overlay 技术，不能据此说 Kubernetes 通常使用 Docker 的 overlay 驱动。[Docker overlay driver](https://docs.docker.com/engine/network/drivers/overlay/)、[Kubernetes Network Plugins](https://kubernetes.io/docs/concepts/extend-kubernetes/compute-storage-net/network-plugins/)

**影响与最小建议：**混淆具体产品驱动与网络实现技术。B 项改为“Docker Swarm 中的跨宿主机通信”；解析及 Y3-27 注明“原文还列出 Kubernetes，此处须区分一般 overlay 技术与 Docker overlay 驱动”，加官方核对链接。保留跨主机用途，不扩展考查 CNI 配置，也不把 CNI 当漏题。

### M3：Y3-25 的 overlay 干扰项并非确定错误

**题号及位置：**Y3-25：Q/A209；T3536 的 D 项 `overlay：用于同一台宿主机内的容器通信`，T3537 标 false。A209 进一步说“overlay 是跨宿主机的网络，不是同一台宿主机内的”。

**原文证据：**S390—395 只强调 overlay 的跨主机能力，没有说它禁止同一宿主机内通信。出题时把用途扩成了排他限制。[原文网络模式小节](https://xiaolincoding.com/interview/docker.html#docker-的网络模式有哪些)

**官方核对：**官方示例明确可以在单节点 Swarm 运行 overlay 例子；同一 overlay 内可容纳同一宿主机上的多个容器。因此“用于同一台宿主机内”没有“只能”时不能稳定判错。[Docker overlay driver，Usage examples](https://docs.docker.com/engine/network/drivers/overlay/#usage-examples)

**影响与最小建议：**多选题的 false 项也可成立。D 改为“overlay 只能连接同一台宿主机内的容器，不能跨宿主机通信”，继续标 false；A209 改为“可跨宿主机，不局限于同一台”，不要保留“不是同一台”的断言。正确项集合可保持 A/C/E。

### M5：attach 的 Ctrl+C 被写成无条件必杀主进程

**题号及位置：**Y4-19（Q/A286；T4914—4915 D 标 true）、Y4-20（Q/A287；T4926—4927 A 标 true）、Y4-22（Q/A289；T4970—4971 C 标 true）、Y4-23（Q/A290）；Y4-21 仅解析 A288 继承此断言，填空 `exec、attach` 不需变。

**现有文本：**“attach 进去后按 Ctrl+C 会直接杀掉容器的主进程”；Y4-20 还把“退出 attach”和“按 Ctrl+C”放在同一比较口径下。

**原文证据：**S560—569 正是这一过强说法。[原文进入容器小节](https://xiaolincoding.com/interview/docker.html#如何进入一个运行中的容器)

**官方核对：**attach 默认代理信号；Ctrl+C 的效果受终端模式、信号代理及 PID 1 的信号处理影响，PID 1 对默认终止动作的信号有特殊行为。满足交互终端条件时还可用脱离按键保留容器运行。因此存在中断主进程的风险，但不是无条件必杀。[Docker attach](https://docs.docker.com/reference/cli/docker/container/attach/)

**影响与最小建议：**会让学习者把“连接现有主进程 I/O”误记成“不能安全脱离”，也会误判自定义信号处理场景。保留原文推荐 exec 的结论和正确字母，把有关选项/解析改成“attach 连接已有主进程的标准流，Ctrl+C 可能将中断信号传给主进程并导致容器停止，容易误操作”；Y4-20 题干明确比较“退出 exec shell”与“attach 中发送中断信号”。答案括注原文说成“会直接杀掉”，附官方核对来源。

**主要题号及位置：**Y4-54（Q/A330；T5716 题干泛称“无用的卷”）、Y4-57（Q/A333；T5777 题干泛称“无用的卷”，T5796—5797 `--volumes` 为正确项）、Y4-61（Q/A337）。关联解析 Y4-51（A327）、Y4-52（A328）、Y4-55（A331）、Y4-56（A332）。Y4-55 的 T5737—5738 C 正确项也以完整列举的形式只列停止容器、悬空镜像、无用网络。
