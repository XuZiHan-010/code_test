### M1：ENTRYPOINT 参数追加缺少 exec 形式前提，导致错误选项并非一定错误

**涉及题号与位置：** Y2-15（Q/A:115；T:1859 题干、1863–1864 A=true、1873–1874 C=false），关联 Y2-13（A:113）、Y2-16（Q/A:116；T:1886、1895–1896）、Y2-23（Q/A:123；T:2053–2054）。

**现有文本：** Y2-15 问“docker run 后面跟的参数遇到 ENTRYPOINT 时会怎样”；A“不会覆盖 ENTRYPOINT，而是作为参数追加到它后面”为正确；C“被忽略，容器仍只按 Dockerfile 里写好的命令运行”为错误。Y2-13、Y2-23 的解答也把追加行为直接归给所有 ENTRYPOINT；Y2-16 的组合用法没注明两者用 exec 形式。

**原文证据：** S:177–188 把 ENTRYPOINT 写成通用追加规则，S:189–200 实际给出的却是两个 JSON 数组的 exec 示例；S:210–220 同时承认存在 shell 写法。这是原文的泛化错误，不是缺了一个原文外的新考点。

**官方核对：** 官方把追加规则限定于 exec ENTRYPOINT；shell ENTRYPOINT 会忽略 CMD 与运行时参数。[Dockerfile reference · ENTRYPOINT](https://docs.docker.com/reference/dockerfile/#entrypoint)

**影响：** Y2-15 未说明形式，C 对 shell ENTRYPOINT 成立；考生按完整 Docker 规则回答会被判错。README 已避开 `--entrypoint` 覆盖问题，但尚未避开形式差异。

**最小建议：** Y2-15 的题卷和 T 题干加“使用 exec 形式的 ENTRYPOINT，且参数位于镜像名之后”；A 保持正确。Y2-13 的解答、Y2-16 的组合说明、Y2-23 的答案同步写清 exec 前提，示例本身和 Y2-17/18 的正确字母无需改变。解答注明原文省略形式条件并附官方核对来源。

### M2：ADD 自动解压把来源与归档格式条件省掉了

**涉及题号与位置：** Y2-25（Q/A:128；T:2086–2088），Y2-26（Q/A:129；T:2093、2097–2098 A=false、2107–2108 C=true），Y2-34（Q/A:137；T:2312–2313）。

**现有文本：** Y2-25“对压缩包可以____”；Y2-26“源文件是 tar.gz 之类的压缩包时，ADD 会怎样处理”，正确项为“自动解压到目标目录”；Y2-34 也说“源文件是 tar.gz 之类的压缩包时会自动解压”。

**原文证据：** S:226–235 连着介绍“压缩包自动解压”与“URL 下载”，却没有解释二者不同的默认行为。

**官方核对：** 默认解包针对可识别的本地 tar 归档；远程 tar 默认只下载，当前文档还存在显式 `--unpack` 控制。[Dockerfile reference · ADD](https://docs.docker.com/reference/dockerfile/#add)

**影响：** 若 tar.gz 是 URL 源，Y2-26 的当前正确项不成立；“压缩包”也容易被理解为任意格式，例如 ZIP。文件后缀本身不能保证被识别为 tar。此处不要求新增考 `--unpack`，只需写清当前题所依赖的默认条件。

**最小建议：** 两处题干改成“未额外设置解包选项，源是构建上下文中可识别的本地 tar 归档（例如真正的 tar.gz）时”；Y2-25 两空继续为“自动解压、URL”，有序配置不变。Y2-34 把相应范围写清，括号注明原文概括为“tar.gz 之类的压缩包”，并附核对链接。Y2-32/33 只说 ADD 具有此能力，不必扩展成新知识题。
