## 一、出题缺少条件

### F1 — U3-12，P2：未限定 HTTP 方法，“第一个定义”不适用于所有同路径操作

**当前题型：简答。完整题干：**

> 为什么要在 /users/{user_id} 之前声明 /users/me？如果为同一路径重复定义了两个路径操作，会使用哪一个？

**当前答案有关部分：**“路径操作是按顺序依次匹配的……同样不能重复定义同一个路径操作：路径首先匹配，始终会使用第一个定义的。”

**官方依据：**[路径参数·顺序很重要](https://fastapi.tiangolo.com/zh/tutorial/path-params/#order-matters) 的反例是两次 `@app.get("/users")`，不是一个 GET 和一个 POST。[第一步·操作](https://fastapi.tiangolo.com/zh/tutorial/first-steps/#operation) 明确允许使用一种“或多种”方法与每个路径通信；[路径操作装饰器](https://fastapi.tiangolo.com/zh/tutorial/first-steps/#define-a-path-operation-decorator) 将路径操作定义为路径加 HTTP 操作。

**为何导致误判：**“同一路径”只给出了路径，没给 HTTP 方法。`GET /users` 和 `POST /users` 能同时有效存在，不能统一回答只用第一个。第一问比较两条路由的匹配顺序也应限定两者都处理同一方法；否则不同方法没有题设所说的遮蔽关系。熟悉方法区分的答题者给出条件化答案可能被“始终第一个”参考答案误判。

**最小修正：**首问改为“两个 GET 路径操作中……”，次问改为“如果对**同一路径、同一 HTTP 方法**重复注册两个路径操作……”。答案同步补同一限定，无需引入任何新知识。

### F2 — U3-29，P2：不给出声明代码，A 和 D 分别在不同合理写法下成立

**当前完整题干：**给路径参数 item_id 声明默认值 None 会怎样？

| 选项 | 当前内容 | 标记 |
| --- | --- | --- |
| A | 不起作用，路径参数始终是必需的，因为它必须是路径的一部分 | 正确 |
| B | item_id 变成可选的，请求路径里可以不写这一段 | 错误 |
| C | FastAPI 会把它自动改成查询参数来处理 | 错误 |
| D | FastAPI 会在启动时报错，路径参数不允许声明默认值 | 错误 |

**当前答案有关部分：**“即使把它声明为 None 或设置了默认值，也不会产生任何影响，它依然始终是必需参数。”

**官方依据：**[路径参数和数值校验·声明元数据](https://fastapi.tiangolo.com/zh/tutorial/path-params-numeric-validations/#declare-metadata) 确实这样简化说明；但官方实现 [params.py 的 Path](https://github.com/fastapi/fastapi/blob/master/fastapi/params.py) 明确 `assert default is ...`，错误文本为 `Path parameters cannot have a default value`。官方 [dependencies/utils.py](https://github.com/fastapi/fastapi/blob/master/fastapi/dependencies/utils.py) 在分析 Annotated 路径参数带签名默认值时也断言禁止默认值。

**实测：**现有环境 FastAPI 0.135.3 / Pydantic 2.12.5 / HTTPX 0.28.1：

- 路由 `/items/{item_id}` 配普通签名 `item_id: int = None` 可以注册，访问 `/items/3` 得到整数 3；默认值不能让该路径段可省略。
- `item_id: int = Path(default=None)` 注册前就触发 `AssertionError`。
- `item_id: Annotated[int, Path()] = None` 注册时触发 `AssertionError`。

**为何导致误判：**本题所在页面本来就在讲 Path，答题者合理地按 `Path(default=None)` 或 Annotated 写法理解，会选择当前被判错的 D；按普通参数默认值理解才是 A。路径仍必填这个概念正确，但“不起作用”和“报错”不能在缺少语法的题干下二选一。

**最小修正：**直接改问“路径参数能否通过设默认值变成可选？”，正确选项只保留“不能，路径段仍必需”；去掉对“会不会报错”的隐含考查。或把普通签名代码与路由完整写入题干，明确不是 Path/Annotated 默认值。若保留对原文的技术说明，按规则注明原文简化并附上述官方代码核对链接。

## 二、忠于原文但需勘误或收窄的技术表述

### S1 — U3-16，P2：解析把任意非真值都说成 False

**当前完整题干：**按官方文档，bool 类型的查询参数 short，下列哪些取值会被转换成 True？

| 选项 | 当前内容 | 标记 |
| --- | --- | --- |
| A | short=off | 错误 |
| B | short=1 | 正确 |
| C | short=no | 错误 |
| D | short=on | 正确 |
| E | short=Yes | 正确 |

**当前答案有关部分：**“接收 1、True、true、on、yes 或它们的任意大小写形式……是 True，**否则为 False**；所以 1、on、Yes 会转换成 True，off 和 no 则为 False。”

**官方依据：**[查询参数·查询参数类型转换](https://fastapi.tiangolo.com/zh/tutorial/query-params/#query-parameter-type-conversion) 中文原文的确有“否则为 False”。核对 [Pydantic 官方布尔校验](https://pydantic.dev/docs/validation/latest/api/pydantic/standard_library_types/#booleans)，它接受一个有限的字符串集合；不在集合内的输入不意味着 False。原文自身的普遍化不能原样变成技术结论。

**实测：**`short=off`、`short=no` 均 200/False；`short=foo` 是 422，错误类型 `bool_parsing`。

**为何导致误判：**当前给定五个选项的答案键 **B/D/E 没错**，但学习反馈会让用户误以为任意其他文本均被吞为 False，进而否定“非法布尔文本校验失败”这一正确理解。该问题在解析，不是需要增减正确选项。

**最小修正：**删掉“否则为 False”，只解释题内五个值：“1/on/Yes 为 True，off/no 为 False”。若要保留通用规则，补“其他合法假值会转换为 False；非法输入会校验失败（原文‘否则’表述过宽）”，并附 Pydantic 官方核对来源。不必新增更多真假值的记忆考点。

### S2 — U2-15、U2-16，P2：把创建协程与 await 得到结果混为一谈

**U2-15 当前完整题干：**调用一个用 async def 定义的函数（如 get_burgers）时，官方文档要求怎样？

| 选项 | 当前内容 | 标记 |
| --- | --- | --- |
| A | 像普通函数一样直接调用，就可以直接拿到它的返回结果 | 错误 |
| B | 必须用 await 等待它，因此只能在 async def 函数内调用 | 正确 |
| C | 直接调用之后，FastAPI 会自动把它放进外部线程池里运行 | 错误 |
| D | 可以在任意用 def 声明的函数内，用 await 来调用它 | 错误 |

**U2-15 当前答案有关部分：**“必须‘等待’它，也就是用 await 调用，所以带 async def 的函数也只能在 async def 定义的函数内部调用；直接像普通函数那样调用……是行不通的。”

**U2-16 完整题干：**既然 await 只能在 async def 函数内用，async def 函数又只能在 async def 函数内调用，那么第一个 async 函数是怎么被调用的？

**U2-16 当前答案有关部分：**使用 FastAPI 不必担心，第一个函数是路径操作函数，FastAPI 知道正确处理；不用 FastAPI 时可以用 AnyIO 编写自己的异步程序。

**官方依据：**[async 和 await](https://fastapi.tiangolo.com/zh/async/#async-and-await)、[更多技术细节](https://fastapi.tiangolo.com/zh/async/#more-technical-details) 原文确实采用了这套简化叙述，因此不能说答案背离所引中文页。但同页 [协程](https://fastapi.tiangolo.com/zh/async/#coroutines) 又明确协程是 async def 函数返回的东西；[其他工具函数](https://fastapi.tiangolo.com/zh/async/#other-utility-functions) 讨论的是用 await 等待结果。核对 [Python 官方协程与任务](https://docs.python.org/3/library/asyncio-task.html#coroutines-and-tasks)，原文示例 `main()` 返回协程对象，调用本身不会调度执行，并展示在顶层用 `asyncio.run(main())` 执行。

**实测：**普通顶层 `value = get_burgers(2)` 成功，`inspect.iscoroutine(value)` 为 True；顶层 `asyncio.run(get_burgers(2))` 得到结果 2。

**为何导致误判：**B 前半句适合“在异步函数中等待结果”的场景，后半句却把函数**调用/协程对象创建**一律限定在 async 函数内。U2-16 又把这个过强结论作为已知前提。答题者区分协程创建和执行时，当前 U2-15 无一项完整准确；这和 U2-17 正在考的“协程是函数返回的东西”也存在教学张力。

**最小修正：**U2-15 题干改为“在 async def 函数内部，要等待 get_burgers 的执行结果，应怎样做？”，B 改为“使用 await get_burgers(...) 等待结果”，保留原答案键。U2-16 改为“await 需要异步上下文，那么使用 FastAPI 时谁负责执行最外层的异步路径操作函数？”。答案不要求加入事件循环 API；只在勘误说明中解释原文把调用与执行简化，并附 Python 官方核对来源。

### S3 — U3-25，P2：声明允许 None 与客户端能传入 None 不是同一层结论

**当前完整题干：**q: Annotated[str | None, Query(min_length=3)]（没有声明默认值）表示什么？

| 选项 | 当前内容 | 标记 |
| --- | --- | --- |
| A | q 是可选的，客户端不传时值为 None | 错误 |
| B | q 是必填的，而且客户端发送的值不能是 None | 错误 |
| C | 因为类型里包含 None，FastAPI 会把 q 当作请求体字段而不是查询参数 | 错误 |
| D | q 是必填的，但客户端发送的值可以是 None | 正确 |

**当前答案有关部分：**“类型里允许 None，意味着客户端必须发送一个值，即使该值是 None，所以 q 必填但可以为 None。”

**官方依据：**[查询参数和字符串校验·必填，但可以为 None](https://fastapi.tiangolo.com/zh/tutorial/query-params-str-validations/#required-can-be-none) 的确这样讲，因此不是转述走样。同题所涉 [查询参数](https://fastapi.tiangolo.com/zh/tutorial/query-params/) 说明 URL 中的值本来是字符串；同页必选参数的例子展示缺省报 missing。教程没有说明 URL 查询字符串如何把一个 Python None 与文本 `None`、`null` 区分。

**实测：**原题签名作为 GET 查询参数时：省略 q → 422/missing；`?q=` → 422/string_too_short；`?q=None` → 200 且值是字符串 `"None"`；`?q=null` → 200 且值是字符串 `"null"`。因此把类型层面的 nullable 直接说成普通 URL 客户端能发送 None，是不完整的接口承诺。这些实测不否定注解/Schema 的 nullable 声明。

**为何导致误判：**从“注解允许的值域”理解，D 是教程意图；从“实际客户端可发送的 URL 输入”理解，D 没有相应发送方式。题干和选项把两层混合，容易将识别 HTTP 输入边界的回答判错。这里不建议直接把 B 改成正确项，因为它也混合类型层和传输层。

**最小修正：**只问声明语义。D 改为“q 为必填参数，同时类型注解允许 str 或 None；是否必填由未声明默认值决定”，解析删除“客户端发送的值可以是 None”，补简短提示“此处描述类型声明，不表示字符串 None/null 会变成 Python None”。保留当前考点与答案键，无需引入新输入协议或新参数。

## 三、尚不足以判为硬错误的边界

### B1 — U3-13：未给具体预设集合，干扰项有宽泛理解空间

完整题干：“按官方文档，要把路径参数的可选取值限定为一组预设值，应该怎么做？”

选项为 A“创建同时继承 str 和 Enum 的类，并把它用作路径参数的类型注解”（正确），B“把路径参数声明为 int，再用 ge、le 这类数值约束限制取值范围”（错误），C“在 Annotated 中为路径参数加上 Query(pattern=\"^fixedquery$\") 这样的正则”（错误），D“把路径参数声明为 bool，让它的取值只能是 True 或 False”（错误）。

[官方 Enum 示例](https://fastapi.tiangolo.com/zh/tutorial/path-params/#create-an-enum-class) 给定的是 alexnet/resnet/lenet 三个字符串成员；当前题干没有把这组字符串或“任意指定离散字符串集合”的要求写出。宽泛地说，bool 本身有有限预设值，整数范围也能限定一组整数。因此答案里“布尔转换……都不是限定一组预设取值的做法”措辞偏绝对。

**不计硬错的原因：**本题有“按官方文档”限定，按所引 Enum 小节的自然意图，A 仍是清楚的最佳答案。属于可消除的范围歧义，不据此宣称多项实际应标正确。

**最小建议：**题干补“例如 alexnet、resnet、lenet 这三个字符串”，答案只解释为什么枚举适合这组字符串，不泛化否定其他类型的值域约束。

### B2 — U3-4：“URL 第一个 /”省略了域名后的定位前提

完整填空题：“按官方文档，URL 中从第一个 / 起的后半部分称为____，HTTP 方法（如 GET、POST）在 OpenAPI 中被称为____。”两空有序，参考答案为“路径、操作”。

[第一步·路径](https://fastapi.tiangolo.com/zh/tutorial/first-steps/#path) 原文也说第一个 `/`，但紧跟完整例子 `https://example.com/items/foo` → `/items/foo`，从例子可看出意图是主机部分之后的 `/`，不包括 `https://` 的斜杠。题干脱离例子后在字面上不精确。

**不计硬错的原因：**原文确实如此表达，答案仍容易唯一识别；没有填空顺序或判分答案不唯一的问题。

**最小建议：**改成“URL 中域名之后、从路径起始 `/` 开始的部分”，或直接给出原文 URL 让用户填写 `/items/foo` 所属概念。仍用两空与原有答案，不增加 URL 解析考点。
