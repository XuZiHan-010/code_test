# Feature Specification: 面试题答题系统 1.0

**Feature Branch**: `001-interview-quiz-system`（项目尚未使用 git，未创建分支）

**Created**: 2026-10-13

**Status**: Draft

**Input**: User description: "做一个部署在 Railway 上的网页答题系统，基于 interview 里面的内容。现有章节里面的题目，都要在网页上每一章都能做；分成单选、多选和简答题，根据每一个知识点的内容去判断应该设计成什么题目；每一章做完，能看到正确率以及每一道题的正确答案和解答，就是知识点的完整展现；设计是不同用户使用，要记录每一个用户每一章的完成情况；用户可以看到自己每一章的错题，包括每道题错了几次；允许用户自己构建一个题集，叫做错题本，就是用户自己添加题目进入这个错题本构成新的题目集。答题完以后可以自动评分并且看到答案。这是最基础的需求，1.0 版本就做到这个程度。后续会引入多人在线的对战模式，1.0 可以只做一个入口：进去以后除了做题模式还有对战模式，详细内容之后补充。做题模式后续还会增加题目和章节。"

## 术语

| 术语 | 含义 |
| --- | --- |
| 专栏 | 题库的四个来源：大模型面试题、Claude Code、Codex、图解 Agent |
| 专题 | 一份题卷，共 15 个，每个有唯一的题号前缀字母 |
| 章节 | 题库里的一个题组，对应一篇原文，共 161 个 |
| 知识点 | 题库里原有的一对题干和参考答案，共 3215 个，以题号标识（如 `B1-1`） |
| 题目 | 网页上呈现的题，由一个知识点转换而来，题型为单选、多选或简答，沿用该知识点的题号 |
| 解答 | 作答后展示的内容：知识点的参考答案全文和原文小节链接 |
| 作答 | 用户对一章（或错题本）的一次完整练习，从开始到交卷 |
| 错题 | 用户至少被判错过一次的题目 |
| 错题本 | 用户自己手动挑选题目组成的题集，每个用户一个 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按章节做题并查看结果 (Priority: P1)

用户登录后选一个章节，按原文顺序逐题作答：单选题选一个选项，多选题选多个选项，简答题写一段文字。做完交卷，立刻看到本章正确率，以及每道题自己答了什么、正确答案是什么、判对还是判错，并能读到完整解答和原文出处。

**Why this priority**: 这是系统存在的理由。没有它，题库仍然只是一堆要自己翻的文件；有了它，哪怕其他功能都没做，用户也已经能做题并得到反馈。

**Independent Test**: 用一个账号选一章，三种题型各答若干道后交卷，核对结果页的正确率、每题对错、正确答案和解答是否与题库一致。

**Acceptance Scenarios**:

1. **Given** 用户已登录并打开某一章，**When** 开始作答，**Then** 题目按题库原有顺序出现，并显示当前是第几题、本章共几题。
2. **Given** 当前题是单选题，**When** 用户选择一个选项，**Then** 只能有一个选项处于选中状态。
3. **Given** 当前题是多选题，**When** 用户查看题目，**Then** 题目明确标出这是多选题，且可以同时选中多个选项。
4. **Given** 当前题是简答题，**When** 用户输入文字，**Then** 答案被接受并保存。
5. **Given** 用户尚未交卷，**When** 浏览本章任意题目，**Then** 看不到正确答案、选项对错或解答。
6. **Given** 用户已答完全部题目，**When** 交卷，**Then** 看到本章正确率，以及每道题的用户答案、正确答案、对错判定、解答全文和原文小节链接。
7. **Given** 用户在结果页，**When** 查看一道选择题，**Then** 能看出每个选项是对是错，以及自己选了哪些。
8. **Given** 用户在结果页，**When** 查看一道简答题，**Then** 能看到判定结果和简短评语（答到了什么、漏了什么）。
9. **Given** 本章还有未答的题，**When** 用户交卷，**Then** 系统提示未答题数量，用户确认后才交卷。
10. **Given** 用户在结果页，**When** 选择只看答错的题，**Then** 列表只显示判错的题。

---

### User Story 2 - 账号与每章完成情况 (Priority: P2)

不同的人各自注册账号使用。系统记住每个用户每一章做到哪了：没开始、做了一半、还是已经完成，以及完成后的正确率。做到一半关掉页面，下次回来能从原来的位置继续。

**Why this priority**: 题库有 161 章，最长的一章 71 题，不可能一次做完。没有进度记录，用户不知道自己做过什么，长章节也无法分次完成。它依赖 Story 1 的做题流程，所以排第二。

**Independent Test**: 用两个账号分别做不同的章节，其中一个中途退出再登录，核对各自的章节状态、续做位置和正确率互不影响。

**Acceptance Scenarios**:

1. **Given** 访客没有账号，**When** 用未被占用的用户名和合格的密码注册，**Then** 账号创建成功并进入登录状态。
2. **Given** 用户名已被占用或密码不合格，**When** 提交注册，**Then** 注册失败并明确提示原因。
3. **Given** 访客未登录，**When** 访问答题或记录页面，**Then** 被带到登录页，登录后回到原本要去的页面。
4. **Given** 用户在某章答了一部分后离开，**When** 再次打开该章，**Then** 之前的答案都在，并回到上次所在的题目。
5. **Given** 用户查看章节列表，**When** 页面加载完成，**Then** 每一章显示“未开始”“进行中”或“已完成”，已完成的章节显示最近一次正确率和最高正确率。
6. **Given** 用户查看专题列表，**When** 页面加载完成，**Then** 每个专题显示已完成章节数和总章节数。
7. **Given** 用户已完成某章，**When** 选择重做，**Then** 开始一次新的作答，之前的作答记录仍然保留。
8. **Given** 用户已完成某章，**When** 再次查看该章，**Then** 可以打开最近一次作答的结果页。
9. **Given** 用户 A 和用户 B 都有答题记录，**When** A 登录，**Then** A 只能看到自己的记录，无法以任何方式看到 B 的。

---

### User Story 3 - 每章错题与错误次数 (Priority: P3)

用户可以查看自己在某一章里做错过的所有题目，每道题错过几次、最近一次是对是错，并且不用重做就能展开看正确答案和解答。

**Why this priority**: 错题是复习效率最高的材料。它建立在 Story 1 和 Story 2 产生的作答记录之上。

**Independent Test**: 同一账号把同一章做两遍，故意在固定几道题上答错，核对错题列表里的题目和错误次数。

**Acceptance Scenarios**:

1. **Given** 用户在某章交卷时有 3 道题被判错，**When** 查看该章错题，**Then** 列表恰好包含这 3 道题，每道错误次数为 1。
2. **Given** 某题已有 1 次错误，**When** 用户重做该章并再次答错这道题，**Then** 该题错误次数变为 2。
3. **Given** 某题曾经答错，**When** 用户后来把它答对，**Then** 该题仍在错题列表中，错误次数不变，并显示最近一次为“答对”。
4. **Given** 用户交卷时有题目未作答，**When** 查看错题，**Then** 未作答的题不在错题列表中，也不增加错误次数。
5. **Given** 用户在错题列表，**When** 展开一道题，**Then** 能看到题目、正确答案和解答。
6. **Given** 用户在错题列表，**When** 按错误次数排序，**Then** 错得最多的题排在最前。
7. **Given** 用户在多个章节有错题，**When** 打开错题总览，**Then** 看到按专题和章节汇总的错题数量。

---

### User Story 4 - 错题本 (Priority: P4)

用户可以把任意题目手动加入自己的错题本。错题本是一个由用户自己挑选的题集，可以查看、移除题目，也可以像做一章那样拿来练习。

**Why this priority**: 它让用户自己决定重点练什么，是在系统自动统计之外的补充。前三个 Story 不依赖它。

**Independent Test**: 从结果页和错题列表各加入几道题，核对错题本内容；移除一道；用错题本练习一次并核对结果和错误次数的变化。

**Acceptance Scenarios**:

1. **Given** 用户在结果页，**When** 把一道题加入错题本，**Then** 该题出现在错题本里，并在所有显示这道题的地方标为“已在错题本”。
2. **Given** 一道题用户从未答错，**When** 用户把它加入错题本，**Then** 加入成功。
3. **Given** 一道题已在错题本，**When** 用户再次添加，**Then** 错题本里仍只有一份，且不报错。
4. **Given** 错题本里有题目，**When** 用户查看错题本，**Then** 每道题显示所属专题、章节和错误次数。
5. **Given** 错题本里有题目，**When** 用户移除其中一道，**Then** 该题不再出现在错题本中，但它的错误次数记录不受影响。
6. **Given** 错题本里有题目，**When** 用户开始错题本练习并交卷，**Then** 看到与章节作答相同形式的正确率、答案和解答。
7. **Given** 用户在错题本练习中答错一道题，**When** 交卷，**Then** 该题的错误次数加 1。
8. **Given** 用户正在进行一次错题本练习，**When** 同时在错题本中增加或移除题目，**Then** 正在进行的这次练习的题目不变。
9. **Given** 错题本为空，**When** 用户打开错题本，**Then** 看到说明和如何添加题目的引导，且无法开始练习。

---

### User Story 5 - 模式入口与对战模式占位 (Priority: P5)

用户登录后先看到两个模式：做题模式和对战模式。做题模式通向上面的全部功能。对战模式在 1.0 只是一个入口，点进去告诉用户这个模式尚未开放。

**Why this priority**: 对战模式是已经确定的后续方向，1.0 先把入口放好，以后加入时用户熟悉的导航不用变。它本身不提供学习价值，所以排在最后。

**Independent Test**: 登录后核对首页有两个模式入口；进入对战模式只看到“尚未开放”的说明；进入做题模式能到达专题列表。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 进入首页，**Then** 看到“做题模式”和“对战模式”两个入口。
2. **Given** 用户在首页，**When** 进入做题模式，**Then** 到达专题列表。
3. **Given** 用户在首页，**When** 进入对战模式，**Then** 看到该模式尚未开放的说明和返回做题模式的途径，没有任何可操作的对战功能。

---

### Edge Cases

- 用户一道题都没答就交卷：允许，正确率为 0，不产生任何错题。
- 简答题提交了空白或只有几个字的答案：空白视为未作答；有内容则正常判定。
- 简答题答案过长：超过长度上限时在输入阶段提示，不允许保存超长内容。
- 简答题判定暂时无法完成：其余题目的结果照常显示，该题标为“待评分”，稍后自动补评并更新正确率。
- 用户在两台设备上同时做同一章：两边看到的是同一份作答，以最后保存的答案为准；一边交卷后，另一边不能再修改。
- 用户作答途中登录状态过期：已保存的答案不丢失，重新登录后回到原来的题目。
- 用户放弃一次进行中的作答：该次作答的答案不计入错题，章节状态按其余作答记录重新判断。
- 题目内容日后有修订：题号不变，用户已有的作答记录、错误次数和错题本条目继续有效。
- 题库新增了章节：新章节对所有用户显示为“未开始”；所在专题的总章节数随之增加，原先“全部完成”的专题变为未全部完成。
- 题库新增章节时，用户正有一份进行中的作答：该作答的题目不变，不受新增内容影响。
- 多选题只选了一个选项，或把全部选项都选上：按“必须与正确选项完全一致”判定，不给部分分。
- 短时间内反复交卷：系统限制单个用户的交卷频率，超出时提示稍后再试。
- 最长的章节（71 题）：题目概览和跳题在这个规模下仍然可用。

## Requirements *(mandatory)*

### Functional Requirements

**题库与题型**

- **FR-001**: 1.0 上线时，系统必须提供题库现有全部 15 个专题、161 个章节、3215 个知识点对应的题目，每个知识点恰好对应一道题目。
- **FR-002**: 每道题目必须是单选题、多选题、填空题、简答题四者之一，题型由知识点内容决定。明确事实或判断可做单选，需要辨别一组正确选项可做多选；明确组成、类别、术语和步骤可做填空；机制、原因、取舍、对比与情景推理保留简答。不按比例凑题型。
- **FR-003**: 单选题必须恰有 4 个选项且仅 1 个正确；多选题必须有 4 到 6 个选项且至少 2 个正确。
- **FR-004**: 选择题的选项只能取材于该题所在章节对应原文的内容，不得引入原文之外的说法。
- **FR-005**: 每道题目必须附带解答，包含该知识点的参考答案全文和至少一条原文小节链接。
- **FR-006**: 题目的题号必须在内容修订前后保持不变；题目被删除后，其题号不得再分配给其他题目。
- **FR-007**: 章节内的题目必须按题库原有顺序呈现。
- **FR-042**: 题库必须能在上线后增加新的专题、章节和题目；新增内容必须满足 FR-002 至 FR-006，且不得改变已有用户的作答记录、错误次数和错题本。新增章节对所有用户显示为“未开始”，专题的总章节数随之更新。
- **FR-045**: 任何题目在面向用户之前必须通过完整性检查（题号唯一且无缺失、题型合法、选项数量与正确项数量符合 FR-003、带有解答和原文引用），并经过人工抽查；未通过的题目不得出现在网站上。

**浏览**

- **FR-008**: 用户必须能按专栏、专题、章节三级浏览题库，并看到每章的题数、对应原文的标题和链接。
- **FR-009**: 章节列表必须显示当前用户每一章的状态（未开始、进行中、已完成），以及已完成章节的最近一次正确率和最高正确率；专题列表必须显示已完成章节数与总章节数。

**账号**

- **FR-010**: 访客必须能用用户名和密码注册账号；用户名全局唯一，密码至少 8 位；不合格时必须说明原因。系统不得以可还原出原文的形式保存密码。
- **FR-011**: 用户必须能登录和退出；登录状态在同一浏览器中保持，直到用户退出或连续 30 天未使用。
- **FR-012**: 未登录的访客不得做题或查看任何记录；访问这些页面时必须被引导登录，登录后回到原目标页面。
- **FR-013**: 用户只能访问自己的作答记录、错题和错题本。

**做题**

- **FR-014**: 用户必须能对任意章节开始作答；同一用户对同一章节（或错题本）同时只能有一份进行中的作答。
- **FR-015**: 单选题只允许选中一个选项；多选题允许选中多个选项并明确标示为多选；简答题提供文本输入。
- **FR-016**: 作答过程中必须显示当前题号和总题数，提供标出已答与未答的题目概览，并允许自由跳题和修改已答的题。
- **FR-017**: 用户的每一次作答必须自动保存；用户离开后再次进入时必须恢复全部已保存的答案，并回到上次所在的题目。
- **FR-018**: 交卷之前，系统不得以任何方式向用户提供正确答案、选项对错或解答。
- **FR-019**: 存在未答题时交卷，系统必须提示未答题数量，并在用户确认后才完成交卷。
- **FR-020**: 用户必须能放弃一份进行中的作答并重新开始；已交卷的作答不可再修改。
- **FR-021**: 用户必须能重做已完成的章节；重做产生新的一次作答，历史作答保留。

**判分与结果**

- **FR-022**: 单选题在用户选中的选项与正确选项一致时判对。
- **FR-023**: 多选题仅在用户选中的选项集合与正确选项集合完全一致时判对，不给部分分。
- **FR-024**: 简答题必须由系统自动对照参考答案判定为对或错，并给出简短评语；判对的标准是覆盖参考答案的主要要点，不要求措辞一致。
- **FR-046**: 填空题支持多个独立输入框、自动保存和恢复，所有空合计不超过 2000 字。由 DeepSeek 对照原文答案按语义评分，接受同义表达和中英文术语；无序列举顺序不限，有序题按对应位置判断。所有空覆盖全部所问考点才算整题正确，空缺、关键错误、重复抵充遗漏判错并指出缺漏；全空按未答处理。
- **FR-025**: 正确率必须按“判对题数 ÷ 该次作答的总题数”计算；未作答的题计入总题数，不算判对。
- **FR-026**: 交卷后的结果页必须显示正确率，以及每道题的用户答案、正确答案、对错判定、解答全文和原文小节链接；选择题须标出每个选项的对错；用户必须能筛选只看判错的题。
- **FR-027**: 简答题判定暂时无法完成时，其余题目的结果必须照常显示，该题标为“待评分”；系统必须在之后自动补评，并更新该次作答的正确率。
- **FR-028**: 用户必须能随时回看每一章最近一次已交卷作答的结果页。
- **FR-029**: 展示解答的页面必须注明内容来源，并说明解答是对原文的转述，其中的经验数字、产品命令和阈值以原文写作时为准。

**错题**

- **FR-030**: 系统必须按“用户 + 题目”累计错误次数：每次交卷时该题被判错则加 1，章节作答和错题本练习都计入。
- **FR-031**: 未作答的题不得累计错误次数，也不得成为错题。
- **FR-032**: 用户必须能查看每一章的错题列表，每道题显示错误次数和最近一次的对错；必须能展开查看题目、正确答案和解答；必须能按错误次数排序。
- **FR-033**: 曾被判错的题在之后被判对时必须保留在错题列表中，错误次数不减少。
- **FR-034**: 用户必须能查看跨章节的错题总览，按专题和章节汇总错题数量。

**错题本**

- **FR-035**: 每个用户有且只有一个错题本，其内容只能由用户本人手动增删，系统不得自动加入题目。
- **FR-036**: 用户必须能从结果页和错题列表把任意题目加入错题本，不要求该题曾被判错；同一道题在错题本中只保留一份，重复添加不报错。
- **FR-037**: 凡是显示题目的地方，必须标明该题是否已在当前用户的错题本中。
- **FR-038**: 用户必须能查看错题本的全部题目，每道题显示所属专题、章节和错误次数；必须能移除题目，移除不影响该题的错误次数记录。
- **FR-039**: 用户必须能把错题本作为题集进行练习，作答、交卷、判分和结果展示与章节作答一致；练习开始时题目列表即固定，其后对错题本的增删不影响这一次练习。
- **FR-040**: 错题本为空时必须显示如何添加题目的引导，且不能开始练习。

**使用限制**

- **FR-041**: 系统必须限制单个用户在短时间内的交卷次数，超出时给出稍后再试的提示。

**模式入口**

- **FR-043**: 用户登录后的首页必须提供“做题模式”和“对战模式”两个入口；做题模式通向专题列表及本规格的全部做题功能。
- **FR-044**: 1.0 中对战模式只是入口：进入后必须显示该模式尚未开放的说明和返回做题模式的途径，不得提供任何对战功能。

### Key Entities *(include if feature involves data)*

- **专题**：一份题卷。属性有名称、题号前缀、所属专栏；包含多个章节。
- **章节**：一个题组，对应一篇原文。属性有编号、标题、原文标题和链接；属于一个专题，包含多道题目。
- **题目**：由一个知识点转换而来。属性有题号、题型、题干、选项及正确选项（选择题）、参考答案、原文小节引用；属于一个章节。题目内容对所有用户相同。
- **用户**：一个注册账号。属性有用户名和登录凭据；拥有自己的作答、题目统计和错题本。
- **作答**：用户对一个范围的一次练习。范围是某个章节或用户的错题本；属性有状态（进行中、已交卷、已放弃）、题目列表、开始和交卷时间、正确率；包含多条作答明细。
- **作答明细**：一次作答中某一道题的记录。属性有用户的答案、判定（对、错、未答、待评分）、评语。
- **题目统计**：某个用户在某一道题上的累计记录。属性有错误次数、作答次数、最近一次判定。错题列表和错题总览由它得出。
- **错题本条目**：某个用户错题本中的一道题。属性有加入时间；同一用户同一道题只有一条。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 题库的 161 个章节全部可以在网页上作答，3215 个知识点 100% 有对应题目，无缺失、无重复。
- **SC-002**: 用户登录后，在 30 秒内可以找到任意一章并看到它的第一道题。
- **SC-003**: 交卷后 3 秒内，用户看到本章正确率和全部选择题的结果。
- **SC-004**: 95% 的简答题在交卷后 30 秒内给出判定和评语。
- **SC-005**: 用户中途离开后再回来，之前保存的答案 100% 恢复，并回到上次所在的题目。
- **SC-006**: 错题列表中的题目和错误次数与用户实际被判错的记录 100% 一致。
- **SC-007**: 任何用户都无法看到其他用户的作答记录、错题或错题本。
- **SC-008**: 按专题抽查题目时，至少 95% 的选择题满足：正确选项与参考答案一致，且没有超出原文内容的选项。
- **SC-009**: 抽查简答题判定时，至少 90% 的判定结果与人工对照参考答案得出的结论一致。
- **SC-010**: 50 名用户同时在线做题时，页面响应没有可察觉的变慢。
- **SC-011**: 第一次使用的用户中，90% 能在没有说明的情况下独立完成一章并找到自己的错题。
- **SC-012**: 向题库新增一个章节后，已有用户的作答记录、错误次数和错题本条目 100% 保持不变，新章节可以正常作答。

## Assumptions

- “章”指题库里的题组（一篇原文一章，共 161 章），不是专题。最大的专题有 511 题，无法作为一次作答的单位。
- 简答题由系统调用大模型服务自动判定（已确认）。这会带来持续的运行成本。
- 账号采用用户名加密码，不做邮箱验证、找回密码和第三方登录。
- 任何人都可以自行注册，不设邀请码或审核。
- 题库内容可以公开发布：来源内容是开源的，每道题的解答保留原文链接作为出处。
- 题目的题型转换和选项编写在发布前离线完成并经过抽查，不在用户做题时即时生成。
- 1.0 只有一个所有用户共用的基础题库（小林coding）。基础题库的新增题目和章节由站点维护者在本地离线准备：把文章转换成题目和解答，校验、抽查后随新版本发布。
- 用户专属题库是已确定的后续方向：用户在网页上传 PDF 或提供网页链接，由大模型生成只属于该用户的题库。届时用户填写自己的大模型 API Key，生成题库的费用由用户自己承担。它在 1.0 之后的版本单独立规格（已确认）；1.0 不提供在网页上生成题目的功能，也不为它预先做任何设计。
- 对战模式的玩法、规则和多人在线能力不在 1.0 范围内，1.0 只保留入口；详细需求之后单独补充。
- 界面语言为简体中文。网页需要在手机浏览器上可用，但不做独立的移动应用。
- 预期规模为小型站点：同时在线用户在几十人量级。
- 部署在 Railway 上，这是用户指定的约束。
- 题库现有的 3215 个知识点及其参考答案是 1.0 的输入；1.0 只要求系统能接纳后续新增的内容，新增内容本身的编写不属于 1.0 的交付。
- 以下内容不在本功能范围内，留待后续拓展：自动把错题加入错题本、按错误次数推荐复习、间隔重复；多个错题本或自定义题集；管理后台和在线编辑题目；排行榜和用户间互动；限时考试和随机组卷；多选题与简答题的部分得分；用户对判定结果提出异议或改判。
